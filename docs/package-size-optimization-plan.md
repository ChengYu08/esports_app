# 移动端包体优化计划

## 目标与原则

在不影响现有业务功能、页面表现和离线兜底能力的前提下，降低 Android 和 iOS 正式包的下载及安装体积，并减少 EAS 构建上传的无效文件。

优化前后使用同一生产配置和相同构建方式比较。每项调整单独提交、单独构建和验收；出现功能回归或视觉差异时立即回退该项。不得仅根据 `node_modules` 或仓库资源目录体积推断用户安装包的收益。

## 当前盘点

- 项目使用 Expo SDK 57，生产构建配置位于 `eas.json`，应用和原生资源配置位于 `app.json`。
- `assets/` 源文件约 35 MB。这个数值包含设计稿遗留和构建资源，不等于最终应用包体积。
- `assets/images/splash-screen.png` 约 4.4 MB，同时出现在启动图配置及应用启动界面代码中。优化时要检查两处使用场景。
- `assets/home/club-detail/icon-diamond.svg` 约 730 KB，当前源码有引用，可评估 SVG 路径优化并进行视觉对照。
- `assets/mine/figma/profile-work-1.png`（约 3 MB）、`profile-work-2.png`（约 15.4 MB）及 `assets/home/club-detail/member-1.jpg` 至 `member-5.jpg`（合计约 5.2 MB）在当前全仓源码、配置和文档扫描中没有发现引用。它们疑似为遗留设计素材，但在删除或排除前仍需确认没有动态加载路径。
- `assets/fonts/Douyin Sans.otf` 约 2 MB，在应用根布局中加载。它可能影响中文字符覆盖和全局字体显示，不应直接删除或无验证裁剪。
- 源码没有发现对 `@expo/ui`、`expo-device`、`expo-glass-effect`、`expo-symbols`、`expo-status-bar`、`expo-system-ui` 的直接引用。这些是依赖清理候选，不代表已确认可删除，也不代表删除后一定会减小正式包。
- `@rongcloud/react-native-im-wrapper` 支持聊天功能，属于关键依赖；首轮不做移除。图片、音频、路由、存储、字体等当前功能依赖同样先保留。
- 仓库当前没有正式 IPA/AAB 产物，因此还没有可复核的安装包基线或可靠的包体节省估算。

## 执行阶段

### 1. 建立正式构建基线

使用当前代码和生产配置分别生成 Android AAB 与 iOS IPA，记录构建提交、SDK/依赖版本、构建配置和产物大小。Android 同时记录各 ABI 的实际下载体积或通过 bundletool 估算的设备下载体积；不能把 AAB 文件大小直接当作用户下载大小。iOS 记录可比较的导出包大小，并在后续保持相同构建方式。

建立功能回归清单：冷启动、登录与会话恢复、隐私同意、首页及俱乐部详情、订单、个人资料、聊天文字/图片/表情/语音、图片选择与上传、消息推送或 SDK 初始化路径（若生产环境启用）。

### 2. 清理未引用的静态资源

复查疑似遗留图片的静态引用、字符串路径、动态 `require`、配置引用及运行时数据驱动加载。确认无运行时用途后，删除文件或在 `.easignore` 中精确排除，避免忽略仍被 Metro 引用的资源。

这一阶段预期首先降低 EAS 构建上下文和上传体积。若资源本来就没有进入 Metro 产物，则不应把它计作应用安装包的节省。

### 3. 优化仍被使用的图片和矢量资源

先对 `icon-diamond.svg` 运行矢量压缩并逐屏对照渲染效果；再评估启动图、应用图标及被页面引用的大图。对位图根据实际显示尺寸选择压缩参数，保持必要分辨率、透明度、颜色和清晰度。只有确认 Expo 启动图配置及运行时 `Image` 都支持目标格式后，才转换启动图格式。

字体暂不纳入首批压缩：如后续评估子集化，必须覆盖静态界面文字及可能出现的动态中文，并在 iOS、Android 上检查字体回退、字重和排版。

### 4. 验证并清理未使用依赖

针对未发现源码引用的依赖逐个做实验，每次只移除一个候选并生成生产构建。检查间接依赖、Expo config plugin、自动链接和运行时动态导入，避免只因没有直接 `import` 就判断为无用。比较正式包体变化；没有可测收益或出现行为变化时恢复该项。

清理依赖后运行 `expo-doctor`、lint、TypeScript 检查和项目现有测试，并重新构建 Android 与 iOS。`expo-dev-client` 需要单独检查开发/生产配置，不将开发客户端误带入生产包，也不通过未经验证的配置改动影响开发构建。

### 5. 汇总结果并设定回归门槛

按阶段记录改动前后构建产物和设备下载体积，说明收益来自构建上下文、JS/资源包还是原生库。提交前再次执行完整功能回归。只有在正式包体有可测下降且回归通过时才保留优化。

## 风险控制与验收

- 不移除支撑聊天、语音、图片选择/上传、身份认证、安全存储和导航的依赖，除非替代实现已经完成并通过完整流程验证。
- 不使用仅对开发包有效的体积结果代替生产包结果；Android AAB 与实际设备下载体积分别记录。
- 对图像和 SVG 优化保留原文件或可恢复的版本，进行修改前后截图/真机视觉对照。
- 每项依赖和资源清理均以独立变更验证，方便定位回归来源。
- 最终验收条件：Android、iOS 生产构建成功；lint、TypeScript 和现有测试通过；上述关键流程通过；包体数据可复现且能说明实际收益。

## 本轮结论

本文件是优化方案，不包含代码、依赖或资源修改。当前工作区已有的排行榜组件未提交修改不属于本计划范围。
