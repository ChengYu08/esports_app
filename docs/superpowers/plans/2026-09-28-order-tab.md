# 订单 Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 Figma 节点 `13:7155` 实现带本地筛选和三种订单卡状态的订单 Tab。

**Architecture:** `src/app/(tabs)/order.tsx` 只挂载 `OrderScreen`，订单功能拆为展示模型、静态数据、筛选工具、Header、Tabs、Card 和 Screen。现有系统状态栏及 `AppTabBar` 继续负责安全区和底部导航，订单页顶部仅显示左侧标题“订单”。

**Tech Stack:** Expo SDK 57、React Native 0.86、Expo Router、`expo-image`、`expo-linear-gradient`、TypeScript 6、React Native Safe Area Context

**Spec:** `docs/superpowers/specs/2026-09-28-order-tab-design.md`

## Global Constraints

- 顶部左侧必须显示标题“订单”，不得显示返回图标。
- 页面背景为 `#F7F7F7`，顶部栏、筛选栏和订单卡为白色。
- 不绘制 Figma 模拟状态栏、Home Indicator 或底部导航栏。
- 新增图片资源保存到 `assets/order/` 且扩展名为 `.svg`。
- 不新增依赖，不创建或修改 `ios/`、`android/`。
- 不实现订单详情、后端接口、支付、取消、售后、评价或再次下单业务。
- 完成前必须通过 `npm run lint`、`npx tsc --noEmit` 和 Expo Web 导出。

- [ ] **Step 3: 定义展示类型和示例数据**

定义四个筛选值 `all | inProgress | completed | cancelled`，四个状态 `pendingPayment | paid | completed | cancelled`，以及操作键 `cancel | pay | afterSales | review | reorder`。三条数据使用 Figma 文案：卖家“成都-吴彦祖”、服务“服务模式-服务等级”、游戏“三角洲端游”、单价 `1000`、数量 `2`、实付 `2000`；状态和按钮分别为待支付（取消订单、去支付 09:28）、已支付（取消订单）、已完成（售后、评价、再来一单）。

- [ ] **Step 4: 实现最小筛选函数**

```ts
export function filterOrders(items: readonly OrderItemModel[], filter: OrderFilter) {
  if (filter === "all") return items;
  if (filter === "inProgress") {
    return items.filter(({ status }) => status === "pendingPayment" || status === "paid");
  }
  return items.filter(({ status }) => status === filter);
}
```

Run: `npx tsc --noEmit`

Expected: PASS。
