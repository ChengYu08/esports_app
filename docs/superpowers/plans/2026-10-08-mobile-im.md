# Mobile IM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace sample message data with a reliable RongCloud private-message flow for conversations, history, text sending, real-time receiving, unread state, and profile-originated chat.

**Architecture:** Keep `rongcloud-im.ts` as the sole native SDK adapter and add a Zustand message store that owns connection, conversation, history, delivery, and read state. Screens become store consumers; a small reducer module owns deterministic merges and delivery transitions so behavior is testable without React Native or a native IM module.

**Tech Stack:** Expo SDK 57, React Native 0.86, Expo Router, Zustand 5, RongCloud React Native IM Wrapper 5.34, Vitest 5, TypeScript 6.

**Spec:** `docs/superpowers/specs/2026-10-08-mobile-im-design.md`

## Global Constraints

- Support private conversations only. Do not add groups, chatrooms, custom-card messages, presence, push, search, or destructive clear-message behavior.
- Preserve the worktree's image and emoji composition controls, but route their state through the same store as text.
- Use Expo Router routes under `src/app/`; do not create or manually modify `ios/` or `android/`.
- Treat Expo Go and web as unavailable IM environments. Show an explicit state rather than sample content.
- Use SDK enum names through a lazy `require()`; do not introduce numeric RongCloud constants.
- An unavailable connection must not create a sent-looking message. A send rejection remains visible and retryable.
- Preserve all unrelated dirty and staged changes.
- Finish with `npx vitest run`, `npx expo lint`, and `npx tsc --noEmit`.

export type MessageDeliveryStatus = "pending" | "sent" | "failed";

Expected: FAIL because `createMessageStore` does not exist.

- [ ] **Step 3: Implement connection and real-time orchestration**

Use Zustand vanilla `createStore` for the injectable factory, then bind the production adapter through `useMessageStore`. State includes `connectionState`, `conversations`, `messagesByPeerId`, `historyByPeerId`, `activePeerId`, and `lastError`. `initialize(token)` transitions through `connecting`, `ready`, `unavailable`, and `error`; only after ready does it load conversations and subscribe. `reset()` unsubscribes, disconnects, and removes every account-specific value.

- [ ] **Step 4: Implement conversation, history, unread, and send actions**

`openConversation({ id, title, avatar })` creates or updates a peer shell, records the active peer, loads latest history, then invokes `markRead`. `markRead` clears UI unread immediately and invokes the adapter without restoring a stale count on failure. `loadOlder` rejects concurrent calls, stops at `hasMore === false`, and prepends unique history.

`sendText` and `sendImage` require `connectionState === "ready"`. They create a pending item with a stable client ID, replace it with the formal callback message on success, or mark it failed and retain the payload for `retryMessage` on failure. New incoming messages update the peer preview/order and increment unread only for inactive peers.

- [ ] **Step 5: Attach store lifecycle to authentication**

In `src/app/_layout.tsx`, select `accessToken` and initialize the store after privacy/session initialization only when a token exists; call `reset()` on missing token and component cleanup. In the confirmed account-settings logout handler, call `useMessageStore.getState().reset()` before clearing the auth session.
