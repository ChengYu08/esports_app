模块按职责分层组织：
- `api/`：对外暴露的 API 层，`match.api.ts` 通过 `apiClient` 调用后端并统一做 `ApiEnvelope` 校验与字段映射，`match.types.ts` 定义前端领域类型（如 `QuickMatchRequestDetail`、`PublishQuickMatchPayload`），二者分离便于单元测试。
- `hooks/`：React Query + 本地 state 的状态层，`use-match-form.ts` 管理发布表单，`use-quick-match-session.ts` 维护匹配中会话（轮询候选列表、倒计时、选人锁定、结束时关闭语聊房）。
- `components/`：纯展示 UI，包括选项芯片、阶梯选择器、匹配等待/倒计时视图等。
- `screens/`：路由页面入口 `MatchMatchingScreen`、`MatchPublishScreen`。
- 顶层流程脚本：`grab-quick-match-flow.ts` 实现「预取详情 → 切房确认 → grab → 进入试音房」的主流程，含模块级 `pendingRequestNos` 防重；`quick-match-confirm-pay.ts` 实现「快照校验 → 建单 → payable 比对 → 余额检查 → 批量支付」的支付编排；`enter-audition-room.ts` 封装发布后跳转试音房；`quick-match-end-signals.ts` 处理结束信号。所有流程均依赖 `voice-room/*` 完成语聊房进出，并通过 `expo-router` 导航。
