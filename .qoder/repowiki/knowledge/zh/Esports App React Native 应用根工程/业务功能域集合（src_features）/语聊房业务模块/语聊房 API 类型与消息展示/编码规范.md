- API 方法统一通过内部 `post<T>(path, token, body)` 发起 POST，并将 `token` 作为第二个参数显式传入，而非依赖全局上下文。
- 后端响应一律用 `Envelope<T>` 包裹，调用方通过 `unwrap` 解包，成功但无 `data` 时返回 `null` 以表示空结果。
- 动态 URL 中的房间 ID 使用 `encodeURIComponent` 编码，并附带 `roomVersion` 查询参数用于版本冲突控制。
- 可嵌套的对象（如 `VoiceRoomDetail` 的 `roomInfo`/`room`/`result`/`data`）在解析房间 ID 时采用递归遍历策略。
- 消息展示根据 `kind` 字段分派到 notice/system/chat 三种渲染分支，并通过 `messageKeyExtractor` 基于 `id` 提供列表 key。
