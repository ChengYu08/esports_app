模块由三类职责清晰的文件组成：
- `voice-room-session.ts` 基于 Zustand 暴露 `useVoiceRoomSessionStore`，维护 `activeRoom`/`joiningRoom`/`lastKickedRoom`/`microphoneMuted`/`screenFocused` 等单例状态，并通过 `beginRoomJoin`→`completeRoomJoin` 的配对接口实现进房流程的状态机，同时用 `intentionalExitInstanceKeys` 区分房主主动解散与被动销毁。
- `reception-command-handlers.ts` 通过 `registerRongCommandHandler({ id: 'reception-command' })` 注册两个命令处理器：`CUSTOMER_SERVICE_INVITE` 走 `actionNotice` 抢单条并调用 `claimAndEnterCustomerServiceRoom`；`QUICK_MATCH_CREATED` 校验发送者与过期时间后写入 `scene: 'quickMatchCreated'`。两者各自维护去重键（`csInviteKeys` Map + `quickMatchCreatedKeys` Set）以抵御离线重放。
- `register-voice-room-kick-command-handlers.ts` 独立注册 `voice-room-kick` 命令处理器，委托 `handleVoiceRoomKicked` 并在被踢时弹出确认弹窗。
依赖方向单向向外：命令处理器依赖 Zustand store 与 UI 组件（`actionNotice`、`showToast`、`useAppConfirm`），不反向依赖上层业务逻辑；跨模块协作通过导出函数（如 `releaseCsInviteKey`、`markVoiceRoomIntentionalExit`）暴露清理钩子。
