模块以两层组织：`register-action-command-handlers.ts` 通过 `registerRongCommandHandler({ id: 'action-command', ... })` 将本模块挂载到融云命令分发管线，集中转发三类命令；`action-command-handlers.ts` 实现具体处理器，按命令名与 `PLATFORM_NOTICE_USER_ID` 白名单校验后调用对应解析器（`parseQuickMatchNotice` / `parseOrderNotifyPopup` / `parseQuickMatchExpired`）再执行业务动作。依赖方向单向向外：仅消费消息层 (`rongcloud-commands`)、订单 API (`order.api`)、匹配流程 (`grabQuickMatchAndEnterAudition`)、全局通知状态 (`actionNotice` store) 以及匹配端结束信号 (`useQuickMatchEndSignals.getState()`)，不反向被业务模块直接调用。去重通过模块级 `Set`（`quickMatchNoticeKeys`、`orderPayKeys`）在进程内完成，离线重放由 `COMMAND_STALE_MAX_MS`（15 分钟）门控丢弃旧消息。测试文件 `action-command-handlers.test.ts` 针对各 handler 的分支进行覆盖。
