- 对需要防抖重复提交的接口（如创建工单、投票）通过闭包缓存 `pending` Promise，并在指纹变化时重新生成服务端幂等键（idempotencyKey）。
- 所有异步操作在进入或退出分支处通过 `assertSession`/`checkSession` 检查 `ownerToken` 是否与当前 `useAuthStore.getState().accessToken` 一致，不一致则抛出带中文提示的 Error。
- 对可能因网络取消的操作统一支持 `AbortSignal`，在请求前后检测 `signal.aborted` 并抛出 `AbortError`。
- 对外暴露的类型（CourtCase、CourtSource、PlatformTicket 等）集中定义在 `court.api.ts`，其他文件仅 import type 引用，保持类型与网络契约单一来源。
- 领域逻辑以纯函数形式组织（如 `ticketDraftError`、`courtVoteUnavailableReason`、`buildCourtProcessTimeline`、`platformTicketMessages`），便于独立单元测试。
- 每个业务文件配套同名的 `.test.ts` 测试文件，覆盖表单校验、时间线构建、投票逻辑与数据转换。
