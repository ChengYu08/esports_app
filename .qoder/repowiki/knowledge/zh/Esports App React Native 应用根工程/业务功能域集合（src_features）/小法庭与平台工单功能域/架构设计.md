模块按 `screens/`（页面）、`components/`（UI 组件）和顶层纯函数/类型文件分层：
- API 与类型定义集中在 `court.api.ts`，导出 `CourtCase`、`CourtSource`、`PlatformTicket`、`EvidenceSubmission`、`TimelineItem` 等核心 DTO，并通过 `apiClient` 调用后端；`uploadCompanionMediaObject` 用于证据图片上传。
- 领域逻辑以纯函数形式放在同名文件中：`court-ticket.ts` 负责工单草稿校验、幂等提交与目标搜索；`court-sources.ts` / `court-target-selection.ts` / `court-source-selection.ts` 负责订单来源聚合、分页拉取与预览确认；`court-vote.ts` 封装评委资格判断与投票流程；`platform-ticket-display.ts` 将工单消息转为时间线数据；`court-process-timeline.ts` 基于审级（FIRST/SECOND/THIRD）与事件枚举构建审理进度条。
- UI 层由 `screens/` 中的 React Navigation 页面与 `components/` 中的可复用卡片、证据选择器、投票按钮等组成，依赖上层纯函数而非直接调用 API。
- 辅助工具包括 `court-evidence-image.ts`（证据图裁剪）、`court-tokens.ts`（幂等键生成）、`complaint-hooks.ts` + `complaint.styles.ts`（投诉相关 hook 与样式），以及对应 `.test.ts` 单元测试覆盖关键逻辑。
- 依赖方向单向：screens → components → 领域函数 → court.api → apiClient，避免组件直接耦合网络层。
