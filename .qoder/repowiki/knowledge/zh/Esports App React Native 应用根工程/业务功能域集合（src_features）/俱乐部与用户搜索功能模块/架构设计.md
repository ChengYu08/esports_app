模块按 React Native Feature 的常见分层组织：
- `api/search.api.ts` 通过 `@/core/network/api-client` 调用 `/client/v1/club/public/search` 与 `/client/v1/companion/public/search`，对后端响应做类型映射并统一返回 `{ items, hasMore, nextPage }` 结构；同时导出共享的 `SearchUser` 类型。
- `hooks/` 下每个搜索领域一个 hook（`use-club-search`、`use-user-search`），基于 `@tanstack/react-query` 的 `useQuery`，以 `[category, keyword]` 作为 queryKey，并通过 `enabled: keyword.trim().length > 0` 控制懒加载。
- `search-history.ts` 是无状态的领域逻辑层，负责历史记录的增删、去重、旧格式兼容解析（`parseSearchHistory`、`mergeLegacyStorageHistory`）以及从搜索结果中推断头像/分类（`getSearchHistoryEntry`）。
- `search-history-storage.ts` 是存储适配层，定义 `HistoryStorage` 接口并提供 `loadGlobalSearchHistory`，负责将旧版分目录 history 迁移到新的 `GLOBAL_SEARCH_HISTORY_KEY`。
- `components/` 提供可复用的搜索 UI（卡片、分类标签、空态、历史列表），`screens/ClubSearchScreen.tsx` 作为入口聚合所有子能力，支持 club/user/message 三种 `SearchType`，并通过本地参数 `type` 切换分类。
- 依赖方向单向：screen → hooks → api；history 逻辑与 storage 解耦，便于测试替换。
