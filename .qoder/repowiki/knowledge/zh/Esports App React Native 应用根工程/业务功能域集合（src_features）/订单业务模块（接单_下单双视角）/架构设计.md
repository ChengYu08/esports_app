模块按 `screens` / `components` / `hooks` 三层组织，并以纯函数文件承担领域逻辑：
- `order.types.ts` 定义 `OrderScope`(`dispatch|accept|place`)、`OrderFilter`、`OrderStatus`、`OrderItemModel` 等核心类型，是模块内所有文件的契约。
- `order.api.ts` 通过 `apiClient` 调用后端，把异构接口响应经 `mapOrder` 统一映射为 `OrderItemModel`，并暴露 `fetchOrderPage`、`acceptOrder`、`cancelOrder`、`freeOrderService`、`submitOrderReview` 等业务 API；`dispatch.api.ts` 单独处理陪玩抢单分页，被 `useOrderPage` 根据 scope 分派调用。
- `order-detail-format.ts`、`order-time-fields.ts`、`free-amount.ts`、`multi-companion.ts`、`payment-countdown.ts`、`after-sale-card.ts`、`order-detail-actions.ts`、`order-notify-sync.tsx` 等纯函数文件封装格式化、金额计算、倒计时、通知同步等无状态领域逻辑，供 screens 和 components 复用。
- `hooks/use-order-page.ts` 基于 `@tanstack/react-query` 的 `useInfiniteQuery` 做分页缓存，queryKey 以 `[scope, filter, userId]` 区分上下文；`use-order-club-names.ts`、`use-order-detail-actions.ts` 分别处理俱乐部名批量解析与详情页动作组装。
- `screens/OrderScreen.tsx` 作为入口聚合状态（取消、完成、售后、评价、免单、多陪等弹窗），通过 `react-query` 的 `invalidateOrderQueries` 刷新；`OrderDetailScreen.tsx`、`DispatchDetailScreen.tsx` 负责详情视图。
- 依赖方向单向：screens → hooks/components → pure domain files → order.api → core network；模块不反向依赖 UI 层。
