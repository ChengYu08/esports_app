模块按三个并列子目录组织，彼此通过共享的启动检查机制耦合：
- `app-upgrade/`：以 Zustand store (`app-upgrade.store.ts`) 为中心管理下载/安装状态，`AppUpgradeHost` 作为隐私同意后挂载的宿主触发冷启动检查，`AppUpgradeDialog` 负责 UI；APK 下载、MD5 校验、缓存复用与安装权限由 `apk-installer.ts` + `apk-verification.ts` 提供原生桥接能力；`app-upgrade-gate.ts` 根据服务端返回的 `AppVersionVO` 判定是否强制升级；iOS 路径通过动态 `import('./ios-store-review')` 打开 App Store。
- `ota/`：基于 `react-native-update` (Pushy) 的热更通道，`pushy-client.ts` 在 Android release 构建下初始化 Pushy 并关闭自动检查；`PushyUpdateHost` 包裹 `UpdateProvider`，在隐私同意后并行发起整包升级检查 (`kickOffStartupCheck`) 与服务端配置拉取 (`ota-config.api.ts`)，经 `ota-update-gate.ts` 的门禁决策后才调用 `checkUpdate()`；`rn-bundle-version.ts` 提供本地 RN_BUNDLE_VERSION 用于版本比较。
- `iap/`：`use-star-iap.ts` 是封装 `expo-iap` 的自定义 Hook，将服务端下发的 `packages` 与 StoreKit 的 `Product` 对齐，处理购买、交易验证 (`submitIapTransactions` → DELIVERED/PENDING)、JWS 凭证上报与错误映射；`apple-star.api.ts` 封装服务端内购 API。

依赖方向：`ota` 反向依赖 `app-upgrade` 的 `kickOffStartupCheck` 以跳过整包升级场景下的热更检查；`iap` 仅依赖自身 API 层与 `expo-iap`，不耦合升级逻辑。
