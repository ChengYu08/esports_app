- SKILL.md 以 YAML front-matter 声明 name/description/compatibility，正文按 Overview / Workflow / Guardrails / Outputs to provide / Resources 分段组织，便于宿主与人类共同消费。
- 对 Pushy 与 Cresc 两套生态保持对称处理：CLI 名、JS 客户端类、dashboard、update.json 与 JS client class 必须同源，禁止混用；未知服务时默认构造中性结构并提示用户选择其一。
- 所有外部可执行调用（pushy/cresc CLI、node doctor）都通过相对 skill-root 的路径解析，避免假设进程工作目录或宿主环境。
- 诊断与校验使用正则信号匹配（signal/add）而非解析 AST，对缺失能力输出 warn/missing 并以 exit code 区分严重级别，不承诺在 debug 模式下完成 apply-update。
- 版本兼容性通过 `versionAtLeast` 语义比较与 feature-detect 双轨判断，确保旧版 SDK 仍走降级流程而不直接调用新原生方法。
- references 与 scripts 目录被明确声明为相对于 SKILL.md 所在目录解析的资源，不在 agent 适配器中硬编码绝对路径。
