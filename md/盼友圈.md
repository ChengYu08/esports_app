## 2. 请求基础设施（所有盼友圈接口的公共底座）

### 2.1 唯一请求出口 `apiClient.ts`

- 全站唯一 HTTP 客户端（`pzdj-pc/composables/apiClient.ts:1-14`）。盼友圈业务接口统一用 `bizPost` / `bizGet`（`apiClient.ts:393-411`），即 `auth: 'business'` + `baseUrl = djApiBase` + `skipSign: true`。
- **鉴权：业务 token 放 `token` 请求头**（不是 Authorization！`apiClient.ts:293-300`）。优先取 `useUserStore().token`（续期后最新值），无 token 且 `requireLogin=true` 时前端直接抛「请先登录」。
- 附加头：`PZVersion / PZPlatform（dianjing-pc 或 dianjing-pc-windows）/ PZOs / PZTimestamp / Random / Skey: CLIENT / deviceId`（`apiClient.ts:137-183, 267-307`）。
- MD5 `sign` 头对 `/client/v1` 不强制（`skipSign: true`，`apiClient.ts:379-387`），网关对业务接口不校验签名。
- 响应统一 panzhi R 包络：`code === 'SUCCESS'` 解包 `data`；否则抛 `ApiRequestError`（`apiClient.ts:322-356`）。
- **401 判定**：HTTP 401 或 `code ∈ {401, UNAUTHORIZED, NOT_LOGIN, NOT_LOGGED_IN}` → 全局清登录态 + 弹登录框，3 秒 `isHandling` 防抖，并发 401 只处理一次（`plugins/auth-guard.ts:21-45`）。
- **实名/三要素/人脸拦截**：后端 `info` **完全匹配**「未进行实名认证 / 未完成三要素认证 / 未完成人脸认证」才唤起全局认证弹窗（完全匹配避免误伤"老板未实名"类文案，`apiClient.ts:73-95`）。
- baseURL：dev `/dj`（Nuxt 代理到 `http://localhost:8105`，`nuxt.config.ts:31-34`）；test `https://djapi.yingbowl.com/api/dj-service`；prod `https://djapi.panzhi.com/api/dj-service`（`env.config.ts:80,97,131`）。

### 2.2 后端鉴权拦截器 `ClientTokenInterceptor`

- 从 `token` 请求头取值 → Redis `tokenKeyPrefix+token` → userId，校验用户状态 NORMAL（防禁用用户续用旧 token），滑动续签，写入 `ClientUserContext`（`…/dj/config/interceptor/ClientTokenInterceptor.java:53-117`）。
- **`@IgnoreToken` 的真实语义（隐藏细节）**：只有 **token 为空** 且方法标注 `@IgnoreToken` 才放行；**带了 token 依然走完整校验**。所以"免登录"接口对已登录用户仍会解析出身份，后端据此计算 `liked / followed` 等个性化字段（游客为 null → false）（`ClientTokenInterceptor.java:63-71`）。
- token 缺失/失效统一返回 **HTTP 401 + `NOT_LOGGED_IN`**（`:127-136`）。

### 2.3 会话续期闸口（隐藏逻辑）

每个登录态请求发出前 `await _sessionFreshHandler?.()`（`apiClient.ts:276`），由 `useSso.ts:197-289` 注入：
- OAuth access_token（12h）**提前 5 分钟**刷新并重换业务 token（`stores/user.ts:194-205`）；
- 同页单飞 Promise 防 refresh_token 轮转互踢（`useSso.ts:219-227`）；跨标签用 `useSessionSync` 锁只刷一次（`:229-253`）；
- 刷新失败进入 **60 秒冷却**防请求风暴（`:205`）；闸口总等待上限 20 秒，超时放行由 401 兜底（`:213, 284-289`）。

## 4. Feed 流与分页联调

### 4.1 feedList

- 请求体 `{ tab: 'hot'|'latest'|'follow', cursor(首屏空串), size(前端传 10，后端钳制 [1,30]) }`（PC `useCommunityFeedApi.ts:94-115`；后端 `MomentsVideoProperties.feed.pageSize/maxSize`）。
- 响应 `CursorPage<FeedItemVO> { list, nextCursor(null=到底), hasMore }`。
- `FeedItemVO`：`videoId / authorInfo{id,nickname,headImage} / title / content / coverUrl / url(签名播放地址) / duration(秒) / declaration[] / publishTime(GMT+8 "yyyy-MM-dd HH:mm:ss") / likeCount / commentCount / playCount / liked / followed / topics(Map<id,名>) / mentionUsers(Map<id,昵称>)`（后端 `…/dj/vo/client/moments/video/FeedItemVO.java:22-72`）。
- **follow tab 隐藏逻辑**：接口本身 @IgnoreToken，但 `tab=follow` 时服务端强制登录，抛的是**业务失败"用户未登录"**（非 HTTP 401，`MomentsVideoServiceImpl.java:236-238`）。前端不拦游客直接发请求，catch 里用正则 `/未登录|登录失效/` 匹配 message 弹全局登录框后返回空页（`useCommunityFeedApi.ts:108-114`）。切 tab 时前端也会先 `requireLogin()`（`index.vue:118`）。
- **任何异常都返回空页**（EMPTY_PAGE），不白屏（`useCommunityFeedApi.ts:87,113-114`）。

### 4.2 游标分页（后端 = ES search_after）

- **cursor 是 Base64URL(JSON{排序键, videoId})**，即 ES `search_after` 值（`…/dj/service/search/moments/impl/MomentsVideoSearchServiceImpl.java:468-517, 537-559`）。取 `size+1` 判 hasMore。
- 排序：`hot` → `heatScore desc, videoId desc`；`latest/follow` → `publishTime desc, videoId desc`（`:412-428`）。follow 额外 `terms authorId in (我的关注列表)`，无关注返回空页。
- **降级**：ES IOException → MySQL 键集分页（`MomentsVideoMapper.xml:52-80`，排序条件与 ES 一致）。注意 **MySQL 降级搜索游标与 ES 相关性分数游标不兼容**，翻页中途切换数据源会跳条（联调环境 ES 挂掉时的已知现象）。
- **隐藏过滤条件：feed 永远 `status=APPROVED`**（`:349`）。刚发布的视频即使机审秒过，也要等回调 + ES update_by_query 完成，feed 查不到；我的列表（走 MySQL）立即可见（REVIEWING）。
- **未做作者封禁过滤**：封禁用户被拦截器阻止登录/互动，但其历史已过审视频仍在 feed。

### 4.3 前端分页状态机

- `useCommunityCursorPaging.ts`：首屏 `cursor=null`，传上页 `nextCursor`；**reqSeq 序号竞态防串页**（返回时序号不匹配丢弃，`:42-46,57-64`）；`loading/loadingMore/!hasMore` 三重防重入（`:38`）。
- **滚动触底用 scroll 事件，不是 IntersectionObserver**：feed 距底 ≤200px 触发（`FeedVideoStage.vue:84-100`）；搜索瀑布流 ≤120px（`search.vue:139-147`）；评论区 ≤80px（`CommentPanel.vue:121-126`）。首屏不满一屏没有 scroll 事件，items 变化/rAF 后主动补检 `scheduleNearBottomCheck()`（`FeedVideoStage.vue:102-106,263-267`）。
- tab 切换 = `paging.reset() + loadMore()`；数据源整体替换用"上一次非空列表快照"对比首项，替换后 `goto(0)`，纯追加保持播放位置（`FeedVideoStage.vue:309-332`）。
- **feed 页刻意不配 onReenter 刷新**：keepalive 缓存跨导航回来复用列表与播放位置，重置会导致跳回第一个视频（`index.vue:110-112` 注释）。

### 4.4 搜索（摘要，完整链路见 §8）

- `search` 请求体 `{ keywordType, keyword, cursor, size }`：`keywordType` 空 = 跨字段模糊（ES `multi_match` 打到 title/content/topicNames/authorNickname.text）；`1` = 话题精确（`term topicNames=keyword`）；排序 `_score desc, videoId desc`（`MomentsVideoSearchServiceImpl.java:382-403`）。
- 话题页 `/community/search?topic=xxx` 用 `keywordType=1`（`search.vue:93-99`）；keyword 为空后端直接返回空页（`MomentsVideoServiceImpl.java:246-251`）。
- 搜索页一次拉 30 条（对齐后端 size 钳制上限减少翻页，`search.vue:97-99`）。

### 4.5 热度分（hot tab 排序来源）

`…/dj/job/MomentsVideoHeatRefreshJob.java:109-131`：

```
heatScore = ( 0.25·ln(1+有效播放) + 0.35·ln(1+点赞) + 0.3·ln(1+评论) + 0.1·ln(1+作者接单数) ) × 0.9^(距发布小时数/24)
```

- `orderCount` = 作者已接订单数（排除 CANCELLED/REFUNDED/PARTIAL_REFUNDED，`MomentsVideoMapper.xml:155-173`）；只刷 APPROVED 视频。

## 5. 视频发布全流程（联调重点）

### 5.1 权限守卫

- 前端路由中间件：未登录弹框回首页；**`user.isPlaymate !== true` → toast「暂无盼友圈发布权限」并重定向**（`middleware/community-publish.ts:11-28`）。注释明确：前端守卫只是体验层，真正的安全边界在后端 publish 接口鉴权。

### 5.2 上传链路：后端签 STS → 前端 tt-uploader 分片直传火山 VOD

（`pzdj-pc/composables/useVodUpload.ts`，头注释 1-17 完整描述；后端 `…/dj/controller/client/media/ClientMediaController.java:30-34`）

1. `bizPost('/client/v1/media/video/uploadSign', { filename })` → `UploadVideoSignVO { accessKeyId, secretAccessKey, sessionToken, expiredTime, currentTime, appId, spaceName, handlerTemplateId?, filename(后端生成的对象 key) }`。
   - 后端调火山 VOD `getUploadSts2WithExpire(1h)`，**STS 是全局共享缓存**（所有用户同一份），Redis key `dj:media:video:sts_token`，TTL 55min 提前 5 分钟过期（`MediaRedisKeyConstant.java:14`）。
2. 前端动态 `import('tt-uploader')`（SDK 大，懒加载，`useVodUpload.ts:98-99`）。
3. **字段名坑**：tt-uploader 要求首字母大写驼峰 `AccessKeyId/SecretAccessKey/SessionToken/CurrentTime/ExpiredTime`，直接塞后端 lowerCamel 字段会**鉴权失败**（`:101-108`）。
4. 后端下发 `handlerTemplateId` 时显式带 `processAction: [{Name:'StartWorkflow', Input:{TemplateId}}]` 触发转码工作流（不依赖空间默认工作流开关，`:110-123`）；`useLocalStorage: false` 避免同名文件断点缓存冲突。
5. SDK 内部完成 `ApplyUploadInfo → 分片直传 TOS → CommitUploadInfo`，**前端不能再调 Commit**；`complete` 事件取 `uploadResult.Vid`；progress 钳制 ≤99% 防止"100% 但未完成"（`:134-137`）。
6. **发布接口只提交 vid**（"上传回调前唯一凭证"，后端 `PublishVideoAction.vid` 注释 `:21-23`）。

本地校验：扩展名 mp4/mkv/mov、≤200MB、时长 ≤5 分钟（隐藏 `<video>` loadedmetadata 探测，`PublishVideoPicker.vue:108-136`）；**无独立封面上传**——封面由火山转码工作流生成，选完文件立即自动上传，失败可重传。

### 5.3 @ 提及与 # 话题的编码契约（前后端联调核心）

**不是内嵌 JSON 字符串**，而是结构化实体数组（`pzdj-pc/composables/mention-core.ts:1-39`）：

```json
{
  "vid": "<火山媒资Vid>",
  "title": "<≤20字，trim后>",
  "content": "<编辑器纯文本原文，含 @张三 / #话题 原文>",
  "mentions": [{ "id": "用户ID", "label": "张三", "offset": 码点偏移, "length": 码点长度 }],
  "topics":   [{ "id": "话题ID", "label": "话题名", "offset": 码点长度, "length": 码点长度 }],
  "declarations": ["<声明文本>"]
}
```

三条硬规则（`mention-core.ts:6-14`）：
1. **offset/length 一律按 Unicode 码点计数**（`[...str]`，不是 UTF-16 `.length`——emoji/扩展汉字会错位）。
2. `slice(offset, offset+length)` 必须恰好等于 `触发符+label`（`@张三` / `#话题名`）；用户删掉半截实体 → `validatePayload` **降级剥掉成纯文本**再提交（`:73-93`）。
3. 实体按 offset 升序、互不重叠。

- **正文 content 不能 trim**：必须与实体 offset 对应（`publish.vue:149-152` 注释）。标题才 trim。
- 编辑器为 Tiptap，@/# 双触发 Mention suggestions（`mention-editor/MentionEditor.vue:240-294`）；**IME 组合期间不同步 model、不许提交**（`ime-guard.ts`、`useCommentSubmission.ts:29`）。
- 超长是软限制：标红 + 禁用提交，不截断输入（正文 1000 字、标题 20 字、评论 500 字，均按码点计数防粘贴绕过）。
- `declarations` 为声明**文本数组**（后端约定 `code = name = 声明文本`，来自 Nacos `MomentsVideoProperties.declarations`），至少勾 1 项。
- 遗留组件 `PublishTopicPicker.vue` / `PublishMentionPicker.vue` 是旧"面板式"方案，**当前未被引用**，现行方案是编辑器内联候选。

### 5.4 后端发布/审核链路（隐藏逻辑密集区）

发布（`…/dj/service/moments/video/impl/MomentsVideoServiceImpl.java:146-170`）：
1. 事务内插入作品（初始 `status=REVIEWING, auditPhase=MACHINE`，计数清零），三份存储 @/# 引用：
   - `dj_moments_video.ext_json`（含 offset/length，供回显高亮）；
   - 关联表 `dj_moments_video_topic` / `dj_moments_video_mention`（去重批量 insert，`:376-393`）；
   - ES 文档冗余 `topicIds/topicNames/mentionUserIds/mentionNicknames`（**昵称/话题名冗余进 ES 是为了 feed 免回表**，`:398-436`）。
2. `ref.id` 非数字时**静默丢弃**（`parseRefId :724-727`）——前端传脏数据不报错但不落库。
3. afterCommit 发 RocketMQ（tag `publish`，`MomentsVideoMqEventPublisher.java:29-40`，**事务提交后才发**，消费者反查数据一定已提交）→ 触发机审 + 发布成功通知。
4. 转码回调：火山工作流完成 → `MediaCallbackServiceImpl.handleWorkFlowComplete` 落 `dj_media_video` → MQ → `MomentsVideoSyncHandlerImpl.sync(vid, playUrl, coverUrl)` 按 vid **幂等回填**。发布时若转码已 SUCCESS 会 best-effort 直接拷贝（`copyMediaAsset :358-371`），否则等回调补。

**审核状态机（先机审后人工，`VideoAuditStatusEnum.java:9-14`）**：
```
发布 → REVIEWING(MACHINE) ──机审 PASSED──→ APPROVED（终态，auditFinishTime）
                       └─FAILED/REJECTED→ REVIEWING(MANUAL) ──人审──→ APPROVED / REJECTED
```
- 机审：`MomentsVideoAuditServiceImpl.triggerMachineAudit`（仅 REVIEWING+MACHINE 才送审；送审内容 = 标题+正文+实时签名视频 URL，scene=MOMENTS_VIDEO）；结果回流 `MomentsVideoAuditResultConsumer`（AI_AUDIT_RESULT_TOPIC）——状态/阶段不匹配**幂等跳过**。
- **敏感词不在本地**：文审/机审全部走远端 AI 审核引擎（精灵/jingling 集成），项目内无词库。
- 人审超时打标：XXL-Job 把 REVIEWING+MANUAL 超过 30min（`dj.moments.video.auditTimeoutMinutes`）的置 `timeout=1`，**只影响后台待审队列分类，不改客户端可见性**。
- 人工审核用条件更新 `WHERE status=REVIEWING AND audit_phase=MANUAL` 防并发；支持 `changeResult` 对已终态视频改判（改判同样触发通知与话题统计）。
- 审核字段可见性：`violationTypes`（文案数组，未知编码原样透出）、`extraDesc`（运营对作者可见备注）**仅 myList 返回**；`machineReason`、`internalRemark` **绝不下发**。
- 每次审核终态都发 `audit_finished` MQ → 刷新话题统计 + 发审核结果通知。

### 5.5 播放地址联调注意

- **feed 返回的 `url` 永远是火山实时签名地址**（Redis 缓存 10min `dj:media:video:play_info:{vid}`，批量并发换签名单条失败不阻塞整页；火山取流偏好 HLS/m3u8 且选最高清晰度）。
- **DB 存的 playUrl 只是转码相对地址**，前端只能用接口返回的签名 URL，不能持久化。
- 前端 HLS：URL 判 m3u8 时**先剥离 query/fragment 再看后缀**；MEDIA_ERROR 尝试 `recoverMediaError()`，fatal 才显示"内容状态异常"；detach 必须 `pause + removeAttribute('src') + load()` 防音频残留（`useHlsPlayback.ts:23-74`）。

## 6. 点赞 / 评论 / 举报 / 播放上报

### 6.1 视频点赞

- 请求体 `{ videoId, liked }` **显式方向**（后端不自动翻转）→ `{ liked }`（`useMomentLike.ts:22-28`）。
- **前端非乐观更新**：接口成功才写 `liked`；**计数后端不回传，前端本地 ±1**（`Math.max(0, count + delta)`，`FeedVideoItem.vue:486-501`）。`likeLoading` 锁防连点。
- 弹窗变体（`VideoDetailDialog.vue:113-132`）：服务端去重导致 `after === before` 时**不动计数避免虚增**。
- 后端幂等两层（`MomentsLikeServiceImpl.java:33-82`）：Redis `setIfAbsent` **同动作 1 秒内直接返回当前状态**（key `dj:moments:video:like:dedup:{uid}:{vid}:{0|1}`）；DB 层明细行 status 判断，即使 Redis 过期重复点赞也不会二次 +1。计数 SQL 带 `GREATEST(...,0)` 防负数。
- 返回的 `likeCount = 库里旧值 + delta` 是**内存计算**，与 DB 短暂不一致属正常。
- 点赞成功且非自赞 → 发 `VIDEO_LIKE` 互动 MQ → 融云通知（见 §7）。

### 6.2 评论（两级楼中楼）

- `comment/list`：`{ videoId, parentCommentId(空=一级), cursor, size(默认10，钳制[1,50]) }` → `CursorPage<CommentVO>`；**一级评论自带 `childComments[]` 嵌套**（当前 UI 不再对楼中楼单独分页，cursor = Base64URL(JSON{"id":评论ID})）。
- `comment/publish`：`{ videoId, parentCommentId?, replyCommentId?, content, mentionUserIds[] }`。
  - **注意：`mentionUserIds` 是纯 ID 数组**，@文本写在 content 里——**与视频发布的 mentions 对象数组（带 offset/length）是两套不同编码**（`useCommunityCommentApi.ts:112-127`）。
  - 回复语义：回复**一级** → `parentCommentId=该id, replyCommentId=null`；回复**二级** → `parentCommentId=其父id, replyCommentId=该二级id`。
  - 前端 `mentionUserIds` 会 `[...new Set(...)]` 去重；`submitting` 锁 + `revision` 序号（视频切换使旧请求失效，`useCommentSubmission.ts:13-55`）。
- **同步 AI 文审**（`MomentsCommentServiceImpl.java:116-118`）：`contentAuditService.auditText(scene=MOMENTS_COMMENT)` **同步调用，REJECTED 直接抛业务异常"内容审核未通过"阻断发布**；审核服务异常/限流**按放行处理**；被 AI 标记"需复核"的评论**照常可见**，但自动生成 `source=MACHINE_REVIEW` 的举报记录进后台复核队列。
- 一级列表的"扫描填充"算法：按 id 倒序 15 条/批扫，过滤无子的 DELETED 直到凑满 `size+1` —— **每页数量是业务可见数而非物理行数**（`:256-313`）。已删除一级评论若有子评论仍展示"该评论已删除"占位（双端各自实现文案）；子评论只查 VISIBLE。
- `comment/delete`：**评论作者或视频作者（楼主）均可删**（前端 `canDelete` 与后端 `hasDeletePermission` 对齐，`CommentItem.vue:250-268`）；逻辑删除 + 原子条件更新；**不级联删子评论**（子评论随父不再展示）；同时删除该评论的举报记录；评论数 -1（仅原 VISIBLE 时）。
- `comment/like`：同视频点赞模式（显式方向 + 1s 去重 + 成功后本地 ±1）。
- `comment/report`：`{ commentId, reportType(须匹配枚举，大小写敏感), reportDesc(≤200字) }`；**举报描述也先过 AI 文审**；DELETED 评论不可举报。后台审核举报成立 → 删评论 + 评论数 -1 + 同评论所有 PENDING 举报一并结案。
- 举报类型枚举由 Nacos `dj.moments.comment.report-types` 下发（默认 10 类：PORNOGRAPHY/POLITICAL/OPPOSITION/TRAFFIC/FRAUD/ABUSE/CYBER_VIOLENCE/SPAM/MINOR/OTHER），**前端动态渲染不可写死**。
- 前端提交评论成功：unshift 列表头 + `bumpCount(1)`，`count-change` 两级上抛回写数据源 `commentCount`；视频切换竞态用 `videoRevision` + `disposed` 防旧请求写入新视频（`CommentPanel.vue:95-105`）。

### 6.3 播放上报（"多少算一次播放"）

- **前端规则：不是"满 N 秒算一次"，而是墙钟累计时长上报**。`createPlayDurationTracker`（`usePlayReport.ts:16-44`）只累计"真实播放"的墙钟时间：`timeupdate` 时满足可计条件才累加；`pause/waiting/seeking/seek` 一律**停计不清零**；结算时机 = 翻页切走 / 退出渲染窗口 / 组件卸载 / keepalive 失活 / 播完 `ended`（`FeedVideoItem.vue:359-371, 447-451, 466-471`）。短暂停不提前消费后端去重窗口。
- 上报 `{ videoId, durationMs(四舍五入毫秒) }`；durationMs ≤0 或游客直接跳过；**该请求全静默**：`skipRefresh/skipGlobal401/skipGlobalRealName` 全开——不参与 token 续期、不触发登出/登录/实名弹窗，失败静默（`usePlayReport.ts:52-75`）。
- **后端规则**：
  - Redis `setIfAbsent dj:moments:video:play:dedup:{uid}:{vid}` **TTL 300s**——同一用户同一视频 5 分钟内多次上报只算一次"上报"（`MomentsVideoServiceImpl.java:300-317`）。
  - 通过后事件 push 进 Redis List `dj:moments:video:play:buffer`，**不直接落库**；XXL-Job `momentsVideoPlayFlushTask` 每批 ≤200 条批量插入 `dj_moments_video_play_log` 并累加 `play_count/effective_play_count`、话题播放数、写 ES 脏集合。
  - **"有效播放" = durationMs ≥ 3000ms**（`effectivePlayThresholdMs`，`MomentsInteractionProperties.java:60`）。

## 7. 通知（融云 IM 系统消息）

- **通道 = 融云 IM 私有持久化系统消息**（`PLATFORM_NOTICE` 系统用户 → 目标用户），非离线 Push；extra JSON 携带 `eventType/actor/videoId/commentId/preview/dedupId` 供跳转（`NotifyServiceImpl.java:140-165`、`MomentsNotificationServiceImpl.java:300-316`）。
- 事件类型（`MomentsNotificationEventType.java:16-61`）：`VIDEO_PUBLISHED / FOLLOW / VIDEO_LIKE / COMMENT_LIKE / COMMENT / REPLY / COMMENT_MENTION / VIDEO_MENTION / VIDEO_AUDIT_APPROVED / VIDEO_AUDIT_REJECTED`。
- 链路：互动 Spring 事件 → afterCommit 转 RocketMQ（topic `topic-dj-moments-interaction-operation` tag `interaction`）→ 消费者**反查业务数据组装纯文本**再走融云。
- **防抖/幂等（隐藏逻辑）**：
  - 发送前**反查点赞明细确认仍处于已赞状态**——防止"赞后立刻取消"仍发通知；视频须 APPROVED、评论须 VISIBLE 才发；自赞/自评不发（`MomentsNotificationServiceImpl.java:151-167,181-203,281-283`）。
  - Redis 幂等键 `dj:moments:notify:dedup:{recipient}:{eventType}:{bizId}:{actorId}` TTL 300s；同一评论产生的 REPLY 与 COMMENT_MENTION 用 `notifiedUserIds` 保证同一人只收一条。
  - 审核通过通知：**APPROVED 时若该视频此前无通过记录（上次是 REJECTED），才向正文 @ 的所有用户补发 VIDEO_MENTION**——改判通过不重复轰炸被 @ 用户（`:120-134,260-273`）。
- **昵称时效差异**：通知文案昵称是消费时**实时反查 `dj_user`**；feed 卡片昵称来自 **ES 作者快照**（资料变更经 `MomentsAuthorSyncConsumer` 刷 ES）——改名后 feed 可能短暂显示旧昵称。

## 8. 话题与搜索完整运行链路

### 8.1 话题的来源：运营后台维护，C 端不能新建

- `dj_topic` 话题表由**运营后台维护**（`…/dj/controller/backstage/topic/topic/TopicController.java`），C 端没有任何建话题接口。
- 发布编辑器的 # 候选只能选**已存在话题**（`/moments/topic/list`，`suggestion-data.ts:52-67`）。
- 后端发布链路只做"解析引用 → 插关联"，**从不 insert `dj_topic`**（`MomentsVideoServiceImpl.java:144-170`）；`ref.id` 非数字被 `parseRefId` 静默置 null 过滤（`:724-727`）。
- **联调含义**：拿一个不存在/非法的 topicId 发布**不会报错**，但话题关联、`ext_json` 实体回显之外的所有下游（`dj_moments_video_topic`、ES `topicNames`、话题统计）都会**静默丢失该话题**——联调时先用 `topic/list` 确认 topicId 真实存在。

### 8.2 发布时话题如何落库（三份存储）

发布事务内（`MomentsVideoServiceImpl.java:146-170`）：

1. `dj_moments_video.ext_json` = `{"topics":[{id,label,offset,length}...], "mentions":[...]}`（供回显高亮，`buildContentRefsJson :703-708`）；
2. 关联表 `dj_moments_video_topic`（`extractRefIds` → 非空/数字/去重 → `saveAssociations` 批量 insert，`:376-393`）；
3. ES 文档冗余 `topicIds` + `topicNames`：`buildDoc` 用解析出的 topicId **反查 `dj_topic` 拿名字**（`selectTopicMap :404`，`MomentsVideoSearchServiceImpl.java:398-423`）——**昵称/话题名冗余进 ES 是为了 feed/搜索免回表**。

### 8.3 话题统计刷新（异步，且只算过审视频）

- 触发：视频审核到**终态**（APPROVED/REJECTED）→ MQ tag `audit_finished` → `MomentsVideoTopicStatsConsumer` → `refreshStatsByVideo` 重算该视频关联话题的 `video_count / author_count / recent_24h_count`（`MomentsVideoTopicStatsServiceImpl.java:34-57`）；播放数由 PlayFlush Job 增量累加（同样只累计 APPROVED 视频）。
- **统计口径**：join 条件 `v.status='APPROVED'`（`TopicMapper.xml:14-16`）——REVIEWING 期间的视频不计入话题统计；审核未到终态前话题数据不更新。
- **话题名是发布时快照**：ES `topicNames` 与正文 # 的跳转 label 都是发布瞬间的名字。运营改话题名后，**旧视频的 `#旧名` 跳转（keywordType=1 按新名精确搜索）会搜不到**，直到该视频被重刷进 ES；`dj_moments_video_topic` 关联关系本身不受改名影响。

### 8.4 话题候选接口与热榜运行

| 接口 | 鉴权 | 参数 | 行为 |
|---|---|---|---|
| `GET /client/v1/moments/topic/list` | **需 token**（无 @IgnoreToken，游客 401） | `keyword?`、`mode?`（default/more） | keyword 空 → 热榜前 N（mode=more 取 50，否则 10）；非空 → `dj_topic.topic_name LIKE` 按 id 倒序取 searchN=20 条（`TopicClientServiceImpl.java:38-60`） |
| `GET /client/v1/moments/topic/hotRank/list` | 免（@IgnoreToken） | 无 | 当前 ACTIVE 热榜按 sort 升序 top 20（topN 可配 `topic.hot-rank.top-n`），Redis 缓存 60s（`HotRankClientServiceImpl.java:49-66`） |

- **热榜生命周期（运营人工配置，非算法）**：后台建榜（话题去重、sort 顺序，`HotRankManageServiceImpl.java:73-99`）→ `PENDING_ACTIVE` → XXL-Job `hotRankActivateTask` 每分钟扫描激活（Redis 锁防多实例并发）→ **同一时刻只有一个 ACTIVE**（激活时旧榜 INVALID、多余到期榜 DISCARDED，`:157-186`）。
- **缓存细节**：`hotRank/list` 走 60s Redis 缓存（**空结果也缓存**，无 ACTIVE 榜时 60s 内运营刚配好也看不到）；而 `topic/list` 内部用的 `getHotRankList(limit)` 重载**不走缓存**直接查库（`HotRankClientServiceImpl.java:69-76`）——两个入口数据时效不一致属预期。
- `topic/list` 需要登录（无 @IgnoreToken），PC 端以 `bizGet(..., false)` 调用（`suggestion-data.ts:55-59`）——游客在发布页本就被中间件拦截，实际无影响。
- PC 端 `fetchHotTopics` 拿到结果后**本地按 sort 升序再排一次**（`useCommunityTopic.ts:30`），失败/空榜返回 `[]` 空态兜底。

**@ 候选（对比项）**：`/moments/mention/list` 后端当前为空实现，PC 端兜底降级为拉取本人关注列表（登录 `/client/v1/userFollow/page`，游客 `/public/page`）再在前端按 keyword 过滤昵称（`suggestion-data.ts:27-50`）；该接口同样**无 @IgnoreToken，需登录**。后端实现后接口有数据即自动切回。

### 8.5 前端话题入口与跳转（3 处，全部传话题名而非 ID）

| 入口 | 位置 | 跳转 |
|---|---|---|
| feed 侧栏热榜 | `CommunitySidePanel` → `HotTopicsList`，`fetchHotTopics()` 拉取 | 点击 → `navigateTo('/community/search?topic=' + encodeURIComponent(名字))`（`index.vue:131-134`） |

### 8.6 搜索页运行（`pages/community/search.vue`）

- **入口**：feed 首页搜索框**回车** → `navigateTo('/community/search?kw=' + encodeURIComponent(kw))`（`index.vue:124-128`）。
- **kw 与 topic 互斥**：`kw` 有值时 `topic` 强制为空（`search.vue:62-69`）；页面标题 `搜索：xxx` / `话题：#xxx`（`:71-75`）。
- **结果页不缓存**：`keepalive: false`，重新进入按 query 加载；feed 首页缓存独立保留（`:53-57` 注释）。
- **双视图**：`list`（`WaterfallList` 4 列瀑布流）/ `player`（`WaterfallPlayer` 内嵌 `FeedVideoStage`）。点列表卡片 → 记录 `playerStartIndex`（播放器从该条开始）→ 切 player；返回列表用 `onScroll` 记录的 `listScrollTop` 恢复滚动位置（`:81-90, 139-162`）。
- **query 变化**（watch `[keyword, topic]`，播放中点其他话题复用同一路由实例）：先回 list 视图、复位滚动与播放索引 → `paging.reset() + loadMore()`（`:111-125`）；**既无 kw 也无 topic 直接 redirect 回 `/community`**（`:102-108`）。
- **触底加载**：scroll 事件，距底 ≤120px → `paging.loadMore`（`:139-147`）；一次拉 30 条对齐后端钳制上限（`:97-99`）。
- **请求**：`fetchSearchPage(keyword || topic, topic ? 1 : null, cursor, size)`——有 topic 走精确（keywordType=1），否则模糊（`:93-99`）。

### 8.7 后端搜索实现（ES 主路 + MySQL 降级）

**入口**（`MomentsVideoSearchServiceImpl.java:292-303`）：keyword 空白 → 直接空页（不查 ES）；否则 trim 后进 ES，**ES IOException 才降级 MySQL**。

**ES 查询**（`searchByKeywordFromEs :382-403`）：

- 恒定 `filter status=APPROVED`（搜索永远只见过审视频）；
- `keywordType=1`（话题页）→ `term topicNames = keyword`。`topicNames` 是 **keyword 类型不分词** → 整词精确匹配、大小写敏感；
- 缺省（模糊搜索）→ `multi_match` 打到 4 个字段：`title`、`content`（ik_max_word 分词）、`topicNames`（keyword——**搜"电竞"不会命中"#电竞陪玩"，必须整词**）、`authorNickname.text`（子字段 ik_max_word 分词；keyword 主字段整词）；
- 排序 `_score desc, videoId desc`；`search_after [score, videoId]`；取 `size+1` 判 hasMore；
- **游标**：`nextCursor` = Base64URL 无 padding 的 `JSON{score, videoId}`（`encodeFromSortValues :468-484`）。

**游标解析容错（隐藏逻辑）**：`decodeCursor :501-512` 解不开 Base64/JSON 时**静默按首屏处理**（日志 warn + 空游标）——前端传坏 cursor 不报错，只会**拿到重复的第一页**，可能造成死循环式重复加载（前端靠 hasMore=false 兜底的前提是游标有效）。

**MySQL 降级**（`:405-410`，SQL `MomentsVideoMapper.xml` selectSearchByKeyword）：

- `keywordType=1` → `exists(dj_moments_video_topic join dj_topic where topic_name = keyword)`（join `is_delete=0`，精确名）；
- 否则 → `title LIKE %kw% OR content LIKE %kw% OR 话题名 LIKE %kw% OR 作者昵称 EXISTS LIKE %kw%`（四个域都用 LIKE，与 ES 分词语义不一致，命中率不同属预期）；
- **降级游标只用 `v.id < #{videoId}`，丢弃 score**，`order by v.id desc`——降级页变成"最新优先"，相关性排序丢失。
- **重大隐藏坑——降级页游标 score 硬编码 0**：`encodeFromDoc :486-490` 在 search 分支写死 `cursor.setScore(0D)`。下一页若 ES 已恢复，`search_after [0, videoId]` 会定位到 `_score=0` 的排序位置，而 multi_match 命中的文档 `_score > 0` → **该游标基本取不到任何数据（空页断流）**。即：搜索翻页途中 ES 抖了一页，后续翻页大概率断流，只能靠用户重新搜索（游标重置）自愈。对比：feed 的 hot/latest 游标（heatScore/publishTime）可在 SQL 中复现，降级后语义连续，无此问题。

### 8.8 话题搜索与模糊搜索的边界（联调注意）

- **只有实体化的话题才进 `topicNames`**：正文里手打"#xxx"但没走编辑器候选选择的文字，只是 content 普通文本——话题精确搜索（keywordType=1）搜不到它；但**模糊搜索会命中**（因为它在 content 里被 multi_match 打到）。
- 反向：话题页（keywordType=1）只匹配 ES `topicNames` 快照（见 8.3 改名失配）。
- 评论区**不支持话题**（`comment/publish` 只有 `mentionUserIds`，无 topics 字段）；# 候选仅存在于发布编辑器。

## 9. 正文中实体的回显降级（前后端兼容层，重要隐藏逻辑）

feed 返回的 `topics/mentionUsers` 当前是 **`Map<id,名>` 字典（无位置）**，但契约也支持**带 offset/length 的实体数组**。前端三级策略（`useCommunityFeedApi.ts:155-259`）：

1. 有位置实体 → 直接用，经 `validatePayload` 校验（slice 必须等于 触发符+label）；
2. 只有字典 → **按字典名做最长前缀匹配推导位置**（候选按名字码点长度降序，短名不抢长名前缀）；
3. 未命中的 @/# 只跳过触发符继续扫，**不用"扫到空白/标点"猜名字边界**（旧实现曾导致"只有第一个 @ 标记、其余全灭"）。

渲染只认 entities：`@` → `/user/{id}`，`#` → `/community/search?topic=...`；**用户手打的 @/# 不会被误染色**（`FeedContent.vue:121-151`）。
后端若补齐 `FeedContentRefVO[]`（带位置），前端自动优先。

> 另注：`FeedItemVO.liked` 的 VO 注释写"本期互动能力未上线，恒为 false"是**过期注释**——实际按点赞表真实计算（`MomentsVideoServiceImpl.java:616-626`）。

## 10. 我的作品 / 用户主页

- `myList`：页码分页 `{ page, pageSize, action: { status: '' } }`。**`action` 必须始终传**——后端 `PageReq.getAction()` 不判空，缺失 NPE（`useCommunityFeedApi.ts:402`）。`status` 可空（查全部非 DELETED），取值 REVIEWING/APPROVED/REJECTED。
- REJECTED 视频前端：瀑布流角标"未通过"**可点击查看驳回原因**（展示 `violationTypes + extraDesc`）；REVIEWING 显示"审核中"不可点。
- **`createTime` 在 ES 分支为 null**——"我的作品"存在 ES/MySQL 双数据源（`es.readFromEs` 默认 false 走 MySQL，联调改配置需注意）。
- `user/page`（他人主页）：只查 APPROVED，**审核字段根本不查不填**（SQL includeAuditFields=false），对任何访问者形态一致。
- **删除后 ES 未同步的前端过滤**：删除成功后把 videoId 记入 `deletedIdsByUser[userId]`，items computed 过滤——**应对 ES 索引同步延迟导致已删作品仍出现在分页结果**（`useUserMoments.ts:34-39`）。本人列表 KeepAlive 激活时强制刷新第一页。
- 用户主页弹窗（VideoDetailDialog）item 是浅拷贝，点赞/评论数变化必须经 `updateLikeState/updateCommentCount` 回写列表源（弹窗不能直接改 props）。

## 11. 播放器与性能隐藏细节（联调排查必读）

- **渲染窗口 ±1**：只有当前项 ±1 共 3 条挂真实 `<video>`，其余封面占位；窗口锚点在**翻页动画结束后**才跟随（scrollend 优先 + 700ms 兜底），避免动画中 `new Hls()+loadSource` 与 `destroy` 抢主线程掉帧（`FeedVideoStage.vue:69-80,193-244`）。
- 翻页：CSS `scroll-snap-type: y mandatory`；wheel 归一化（LINE×16/PAGE×视口高）超 60px 翻页；**翻页锁 600ms**（scrollend 优先解锁）防触控板惯性连翻；键盘 ↑/↓/PageUp/PageDown 翻页、Space 播放暂停（输入框/ProseMirror 聚焦放行）（`useCommunityPlayer.ts:47-170`）。
- `scrollToIndex` 用**实测 rect 差值**而非 `offsetTop`（各级容器 static，offsetTop 是距 body 值，会多滚被 snap 拉回产生顿挫，`FeedVideoStage.vue:156-172`）。
- 默认 **muted 自动播**（绕过 autoplay 策略），音量默认 60；播放模式默认 **loop 循环**，可切自动连播；连播翻页前若在全屏需先 await 退出全屏（布局抖动竞争）（`useFeedPlayerControl.ts:32-90`）。
- **keepalive 滚动恢复坑**：DOM 移入隐藏容器时 scrollTop 被重置，必须在 `onBeforeRouteLeave`（DOM 尚在布局中）记录，`onActivated` 多轮兜底恢复；切走自动暂停、切回恢复（`useFeedPlayerControl.ts:96-129`）。
- 控制条 3 秒自动隐藏（悬停控制条/正文/阅读展开时不隐藏）；时长显示**不向上取整**（10.99s 显示 0:10）。

## 13. 隐藏逻辑 / 联调注意事项 Checklist

1. **token 放 `token` 头**，不是 Authorization；`/client/v1` 免 MD5 签名；响应统一 `code==='SUCCESS'` 解包 data。
2. **`@IgnoreToken` 只在"未带 token"时生效**；带了失效 token 的"免登录"接口依然 401。`playInfo`、`declaration/list`、`topic/list`、`mention/list` 实际需要 token。
3. `feedList` 免登录，但 `tab=follow` 服务端抛**业务失败"用户未登录"**（非 401），前端靠 message 正则识别。
4. **发布只传 vid**；封面由火山转码工作流生成；STS 全局共享；tt-uploader 字段名要首字母大写驼峰。
5. **@/# 实体按 Unicode 码点计 offset/length**；正文不 trim；半截实体降级为纯文本；脏 id 静默丢弃。
6. **feed 只见 APPROVED**；刚发布/刚过审的视频有 ES 同步延迟（对账 Job 兜底最长滞后到对账周期）；myList 立即可见。
7. **ES 双读降级**：feed/搜索永远先 ES、异常降级 MySQL；两种游标不兼容，翻页中途切换会跳条。
8. **点赞/播放/通知均有 Redis 幂等**（1s/300s/300s）；点赞计数前端本地 ±1，服务端不回传计数。
9. **播放上报全静默且与全局登录/实名弹窗隔离**；"有效播放"= durationMs≥3000；同一用户同一视频 5 分钟去重。
10. **评论发布同步 AI 文审**，不过直接业务异常；AI 服务挂了按放行；"需复核"评论照常可见但自动进后台举报队列。
11. **楼中楼只有两级**；一级评论每页数量是"业务可见数"（扫描填充过滤无子的 DELETED）；删除不级联子评论。
12. **举报类型/自主声明均 Nacos 动态下发**，不可前端写死；reportType 大小写敏感。
13. **昵称双源**：feed 用 ES 作者快照（有同步延迟），通知实时反查——改名后表现不一致属预期。
14. **时间格式差异来自前端解析层**：feed `publishTime` 是 GMT+8 格式化串，评论 `createTime` 是 Jackson ISO 串，后端 VO 都是 LocalDateTime。
15. **myList 的 `action` 必传**否则 NPE；游客 `liked/followed` 恒 false；自己作品的 `followed` 恒 false。
16. **删除是逻辑删除**；删除后 ES 可能短暂残留（前端本地过滤兜底）。
17. **热榜是运营人工配置 + 定时激活**，非算法榜单；话题统计只算 APPROVED 视频。
18. **@ 候选接口后端空实现**，前端兜底关注列表 + 前端过滤；后端上线后自动切换。
19. **审核驳回原因只下发给作者本人（myList）**：`violationTypes`（文案）+ `extraDesc`；机审原因与内部备注绝不下发。
20. **MQ 全部 afterCommit 发送**（publish/audit_finished/interaction），消费者反查时数据必已提交；联调环境若改库不发 MQ/不跑 Job，ES/话题统计/通知不会更新。
21. **C 端不能新建话题**：话题全部来自运营后台 `dj_topic`；发布传不存在/非法的 topicId **静默丢失**（不报错、不落关联、不进 topicNames）。先调 `topic/list` 确认 topicId 有效。
22. **话题名是发布时快照**：ES `topicNames` 与正文 # 跳转 label 都固化在发布瞬间；运营改话题名后，旧视频的 # 跳转（按名精确搜索）失配，直到该视频重刷进 ES。
23. **搜索降级游标断流坑**：MySQL 降级页的 nextCursor 把 score 写死为 0（`encodeFromDoc`），ES 恢复后该游标 `search_after [0, id]` 基本取不到数据——搜索翻页途中 ES 抖一页会导致后续断流，只能重新搜索自愈。feed 游标（heatScore/publishTime）降级后语义连续，无此问题。
24. **坏游标静默按首屏处理**：decodeCursor 解不开就当空游标，不报错——前端会拿到重复的第一页。
25. **topicNames / authorNickname 主字段是 keyword 整词匹配**：模糊搜索"电竞"不会命中"#电竞陪玩"或昵称子串；要命中话题/昵称必须整词（分词能力只在 title/content 与 authorNickname.text 子字段）。
