# 盼之电竞 1.0 移动端一期项目需求文档

## 1. 文档说明

- 产品：盼之电竞移动端（iOS / Android）
- 版本：1.0 一期（提审版）
- 更新时间：2026-09-24
- 文档定位：本文件是本次开发的移动端一期独立需求基线。未在本文件明确为“一期”的能力，以及所有 PC 端能力、规则和页面，均不视为本次开发范围。
- 技术基线：Expo SDK 57、React Native、Expo Router；路由位于 `src/app/`。

## 2. 产品目标与发布范围

盼之电竞为用户提供发现电竞俱乐部、选择陪玩、下单履约、快速匹配、即时沟通及个人账户管理的移动端服务。移动端以老板（下单用户）、陪玩和接待三类用户为核心，支持游客浏览与登录后交易。

### 2.1 本次发布范围

| 阶段 | 目标时间 | 范围 | 本次是否开发 |
| --- | --- | --- |
| 一期（提审版） | 2026 年 10 月下旬 | 应用启动、首页、俱乐部、个人页/下单、订单、快速匹配、消息、我的、登录及实名入口 | 是 |
| 二期（PC 补充版） | 2026 年 11 月中旬 | 语聊房/客服派单、小法庭、陪玩管理 | 否 |
| 社交补充版 | 待定 | 排行榜、盼友圈 | 否 |

### 2.2 一期验收目标

1. 用户可在未登录状态浏览首页、俱乐部和陪玩个人页；在关注、聊天、下单、订单、匹配、我的等需要身份的操作前完成登录。
2. 用户可完成“发现俱乐部 → 查看陪玩 → 选择服务 → 提交订单 → 支付 → 查看订单”的主链路。
3. 陪玩可查看自己的接单与派单信息，并参与快速匹配抢单。
4. 应用在首次启动时完成合法合规的协议确认；同意前不采集设备标识、不初始化第三方 SDK。
5. 一期核心页面具备加载、空、失败、重试、无权限和网络异常状态。

## 3. 用户、角色与权限

| 角色/状态 | 可访问能力 | 受限能力 |
| --- | --- | --- |
| 游客 | 首页、搜索、俱乐部列表与详情、陪玩个人页 | 关注、私聊、下单、订单、快速匹配、个人中心均要求登录 |
| 老板 | 浏览、关注、聊天、下单、支付、我的下单、发起快速匹配、管理个人资料 | 不展示陪玩专属派单中心、我的接单 |
| 陪玩 | 老板全部基础能力；派单中心、我的接单、快速匹配抢单 | 无额外一期限制 |
| 接待 | 发起快速匹配、圈定通知陪玩；其余能力按其普通账号身份处理 | 不在客户端实现俱乐部后台管理 |
| 青少年模式用户 | 仅可看到青少年模式锁定页与关闭入口 | 模式开启期间，其他全部功能不可用 |

> 俱乐部管理属于后台能力，仅 PC/后台支持，移动端不实现管理角色差异或俱乐部管理入口。

## 4. 信息架构与导航

### 4.1 一期主导航

底部固定五个入口：`首页`、`订单`、`匹配`、`消息`、`我的`。

- 首页仅提供首页内容与搜索入口；小法庭为二期能力，本次不展示入口。
- 匹配一期仅承载快速匹配；客服派单/语聊房为二期，本次不展示入口。
- 订单根据身份展示对应订单视角。
- 未登录用户点击受保护入口时，进入登录；登录成功后应返回原目标页面或继续原发起动作。

### 4.2 一级与关键下钻路径

```text
首页 → 搜索 / 俱乐部详情 → 陪玩个人页 → 确认订单 → 支付 → 我的下单
订单 → 订单详情 → 订单状态操作
匹配 → 发布需求 → 圈定通知 → 抢单 / 匹配详情
消息 → 会话详情 → 单聊
我的 → 个人主页 / 星钻 / 关注与粉丝 / 设置
```

## 5. 全局与启动需求

### 5.1 一期：闪屏与首次协议

1. 每次冷启动默认展示闪屏 3 秒，用于避免初始化期间白屏；不得因网络请求无限延长。
2. 客户端记录是否已接受协议。首次启动、清除应用缓存、卸载重装后均须重新确认。
3. 首次启动显示协议确认弹窗，协议正文由 H5 页面承载，本期不做后台动态配置。
4. 用户点击“同意”后，才可进行必要的网络/设备授权、设备标识获取与第三方 SDK 初始化，并进入首页。
5. 用户点击“不同意”后退出应用；再次启动仍应显示协议确认。
6. 同意前严禁读取或上传设备指纹、IMEI、MAC、OAID、IDFA、Android ID、剪贴板等设备信息，也严禁初始化任意第三方 SDK。

### 5.2 一期：设备标识与请求基础信息

1. 用户同意协议后，每次启动获取平台允许的设备标识，供统计、风控、反作弊、推送使用。
2. 标识获取失败不阻塞基础浏览；应记录非敏感失败原因并按服务端约定降级。
3. 缓存有效的设备信息，并作为每个 API 请求的基础字段上报。
4. 客户端不得以明文日志、页面或通知暴露原始设备标识。

### 5.3 一期：第三方能力初始化

| 能力 | 初始化时机 | 失败处理 |
| --- | --- | --- |
| 融云 IM / Push | 协议同意后、会话恢复完成时 | 按 SDK 规则处理失败；消息页展示可恢复失败态，Push 不可用不阻塞应用 |
| MSA / OAID（Android） | 协议同意后 | 初始化失败重试一次；仍失败则以无 OAID 继续 |
| 火山云崩溃监控 | 协议同意后 | 初始化失败重试一次；仍失败则仅失去崩溃统计能力 |

## 6. 认证、会话与实名

### 6.1 一期：登录拦截

以下动作必须登录：关注/取消关注、聊天、确认订单、支付、查看订单、发布或参与快速匹配、查看消息、进入我的、修改个人资料及设置。

登录流程完成后，客户端应恢复登录前的目标路由；对于订单确认、发布匹配等带草稿的页面，应保留用户已填写内容。

### 6.2 一期：多端登录规则

1. 推送按设备发送：同一账号在新的移动设备登录成功后，旧移动登录会话应被服务端踢出；客户端接到失效事件后清空本地会话并回到登录页。
2. 实名认证的页面、字段、审核状态与服务端协议待补充；一期在需实名的交易动作前提供统一的实名引导入口，不自行推断认证规则。

## 7. 一期功能需求

### 7.1 一期：首页

**页面目的：** 让游客和已登录用户发现俱乐部、切换游戏品类并进入后续交易路径。

1. 顶部提供搜索按钮；搜索必须可进入搜索流程。
2. 首页展示运营 Banner、游戏切换、热门俱乐部及俱乐部列表；当前首发游戏为“三角洲端游”和“三角洲手游”，默认端游。
3. 切换游戏后，俱乐部列表按所选游戏从第一页重新请求；切换期间显示加载态，旧数据不得错误混入新游戏。
4. 俱乐部列表支持下拉刷新、分页加载、空态、失败重试；卡片展示封面、自营标识（如有）、名称、在线人数、介绍、成员数和 ID。
5. 搜索支持俱乐部/陪玩等服务端定义的检索对象；搜索页应有初始、输入中、无结果、失败与历史记录（若服务端提供）状态。
6. 未登录状态展示轻量登录引导，可关闭；不能以弹窗阻断基础浏览。
7. 俱乐部数量较少时，可按运营配置在首页补充大神推荐区域；无配置则不展示。

### 7.2 一期：俱乐部详情

**页面目的：** 承接“进入俱乐部 → 筛选陪玩 → 下单/咨询”。

1. 展示俱乐部基本信息、陪玩/技能列表及必要的空、加载、失败状态。
2. 外层筛选展示模式、等级、性别；点击筛选后以半屏弹层完成筛选、重置和确认。
3. 筛选确认后刷新当前陪玩列表，筛选条件在当前俱乐部浏览会话内保留。
4. 底部固定操作栏：价目表、快速匹配。价目表展示服务端提供的价格信息；快速匹配进入一期匹配流程。
5. 点击陪玩卡片进入陪玩个人页。

### 7.3 一期：他人页、个人页与下单

**页面目的：** 展示用户/陪玩的资料、技能和评价，并承接关注、聊天、资料编辑与下单。

1. 页面顶部展示头像、昵称、基础资料、俱乐部信息（如有）和默认背景图；资料缺失使用统一占位。
2. 内容页签为“技能”“评价”。技能展示介绍和下单卡片，展示粒度到等级；评价完整展示并按时间倒序分页加载。
3. 查看他人时，底部固定操作为关注/取消关注与聊一聊；未登录点击时触发登录。
4. 查看本人时，底部固定操作为编辑资料。
5. 编辑资料：
   - 头像编辑按用户动作申请相册和相机权限；拒绝时说明原因并提供进入系统设置的路径。
   - 选择图片后提供基础正方形裁剪，上传成功后刷新个人资料。
   - 昵称、性别、签名使用独立弹窗编辑并进行字段校验。
   - 年龄使用平台原生日期选择器；页面展示的年龄按服务端规则计算。
6. 确认订单页只允许修改服务、数量和备注。初始未选择服务时，单价与单位均为空；选择服务后才显示对应单价、单位和总价。
7. 提交订单必须防重复；创建成功进入支付或订单详情，失败时保留可重试的表单内容。

### 7.4 一期：订单中心

1. 订单中心用于统一查看订单及执行卡片操作；订单详情展示状态、服务、金额、双方信息、时间与服务端返回的可执行操作。
2. 陪玩身份显示“派单中心”“我的接单”“我的下单”；非陪玩仅显示“我的下单”，可不显示额外标题。
3. “我的接单”和“我的下单”按以下分类筛选：

| 分类 | 包含订单状态 |
| --- | --- |
| 全部 | 所有状态 |
| 进行中 | 待支付、已支付、待服务、服务中 |
| 已取消 | 已取消、已退款 |
| 已完成 | 已完成 |

4. 一期不实现订单自动完成：服务后如老板和陪玩均不点击完成，订单保持服务端状态。
5. 一期不外露小法庭或任何关联售后入口。
6. 用户不在 App 前台时，订单状态变化应通过融云 Push 发送设备通知；通知点击应深链至对应订单，失效/无权限时安全回退。

### 7.5 一期：快速匹配

1. 老板或接待可发布快速匹配需求；表单字段、可选游戏/服务、校验规则和价格以服务端契约为准。
2. 发布者可圈定通知指定陪玩；无可选陪玩、通知失败、部分成功均需可理解反馈。
3. 陪玩可在匹配列表/通知中查看需求并抢单；抢单结果以服务端原子判定为准，客户端处理“已被抢”“已关闭”“网络失败”等结果。
4. 成功派单后，应用最顶层显示可关闭但可再次找到的悬浮入口，帮助发布者快速进入该派单详情；不遮挡系统返回、底部导航及重要表单操作。
5. 匹配状态变化在应用后台时触发 Push；前台由页面状态和消息提示同步反馈。

### 7.6 一期：消息

1. 消息首页展示最新会话列表、未读数和红点；红点与会话未读数以 IM 服务状态为准。
2. 支持老板与陪玩单聊，具备会话加载、发送中、发送失败重试、空态与断线重连提示。
3. 登录后建立 IM 连接；登出或会话被踢出后断开并清除私有会话缓存。
4. 一期仅实现消息列表、红点、单聊和 Push 接入。

### 7.7 一期：我的

1. 我的页展示头像、昵称、ID、在线状态、俱乐部标识（如有）。
2. 提供星钻、关注、粉丝、我的房间、加入盼之电竞、俱乐部入驻、基础设置入口。
3. “加入盼之电竞”“俱乐部入驻”使用弹窗展示运营二维码，并提供保存图片；仅在用户点击保存时申请相册权限，拒绝后可跳转系统设置。

#### 7.7.1 一期：星钻与充值

1. 所有平台均不支持自定义充值金额，仅展示服务端下发的档位。
2. iOS：接入 Apple IAP，并使用 App Store Server Notifications V2 的服务端通知模式；档位星钻按产品策略为原价 7 折，建议首发仅展示 2–3 个低价档位。
3. iOS 支付成功提示“已充值成功，请稍后查询星钻余额~”；取消提示“交易已取消~”。客户端需以服务端最终入账结果刷新余额，不以本地支付回调直接加钻。
4. iOS 退款由 Apple 决定。针对服务端通知的退款申请、已退款、撤销退款等状态进行订单校验、星钻倒扣和已退款后的自动补款；极端的多次退款申请暂不处理。
5. Android：复用微信和支付宝支付拉起能力；支付结果以服务端订单状态为准。

#### 7.7.2 一期：关注与粉丝

展示关注列表与粉丝列表，支持分页、空态及进入他人页；关注状态变更后应同步个人页与列表状态。

#### 7.7.3 一期：设置

1. 设置包含账号与安全、青少年模式、消息通知、清除缓存、关于盼之电竞、退出登录。
2. 账号与安全承载实名、手机号和注销账户入口；具体绑定/注销步骤待服务端和合规方案补充。
3. 青少年模式：
   - 登录后，从下一次启动开始在首页弹出提示；未勾选“不再重复弹窗”时，每日首次启动弹出。
   - 勾选后后续不再弹出；清除缓存后恢复该规则。
   - 开启时设置 4 位数字密码并二次确认；不一致提示“前后两次密码不一致”。
   - 开启后显示全屏锁定页，杀进程重启仍保持锁定；关闭时输入密码。
   - 密码错误提示“密码有误，今日还剩 x 次机会！”，每自然日最多 10 次错误。
4. 消息通知：消息免打扰默认关闭，开启后 23:00–06:00 不发 Push；短信通知默认开启，关闭后不接收系统短信。
5. 清除缓存仅清理可再生的图片、列表等缓存；清理前说明不会删除账号与订单。若清理会重置协议/青少年提示状态，须在确认弹窗中明确说明。
6. 关于我们展示 Logo、版本、检查更新、用户协议、隐私政策。iOS 的检查更新跳转 App Store；Android 请求服务端版本信息，有新版本时提示下载，无新版本提示“当前已是最新版本！”。协议统一在应用内协议页/H5 打开。
7. 退出登录前确认；确认后清理令牌、用户数据、IM 会话与私有缓存，返回登录页或游客首页。

## 8. 一期：非功能与合规要求

1. 所有请求统一携带会话、应用版本、平台、设备基础信息与请求标识；令牌及隐私信息不得写入普通日志、通知正文或非安全存储。
2. 令牌存入安全存储，非敏感 UI 缓存可使用异步本地存储；登出、账号被踢、注销后清理私有数据与查询缓存。
3. 所有列表支持加载、空、错误、重试；分页请求防重复，Mutation 防重复提交。
4. 页面适配 Safe Area、键盘、常见小/大屏；核心触控区域满足平台最小触控尺寸。应用仅竖屏。
5. 图片使用缓存、占位和失败兜底；列表使用稳定 key 与虚拟化，避免首屏和滚动卡顿。
6. 权限仅在用户触发相机、相册、通知等功能时申请；必须处理拒绝、受限和打开系统设置。
7. Push、IAP、IM、崩溃监控等含原生代码能力接入后，必须使用 Development Build 及 iOS/Android 真实环境验证，不能只依赖 Expo Go。
8. 上线前完成隐私政策、第三方 SDK 清单、iOS 隐私申报和 Android 合规申报的一致性检查。

## 9. 一期：数据与接口约束

1. 客户端以服务端为订单状态、支付结果、匹配抢单结果、关注关系、消息未读数和角色身份的唯一事实来源。
2. 所有接口响应须进行运行时校验；字段缺失或状态未知时使用安全降级 UI，并记录脱敏诊断信息。
3. 订单、支付、抢单、关注等变更操作需要幂等键或服务端幂等语义，避免重复点击和网络重试导致重复业务。
4. 下列契约需在开发前由服务端补齐：登录/会话失效、实名、设备信息字段、俱乐部与筛选、技能与价格、订单状态机、售后、快速匹配、IM Token/Push、星钻商品与 IAP 校验、Android 更新、二维码资源。

## 10. 不纳入本次一期开发

- PC 端俱乐部管理及任何后台管理能力。
- 社交补充版的排行榜、盼友圈。
- 二期的语聊房、客服派单、小法庭和陪玩管理；本次不展示入口、不保留占位页面。
- 自动完成订单。
- 移动端提现、银行卡/收款账户管理。
- 未明确的 PC 端页面、规则、字段或交互；需以新的移动端需求补充后纳入。
