# 注销账号功能完善方案

## 目标

参考 `/Users/yucheng/Desktop/pz_steam` 的注销账号流程，完善当前 Expo/React Native 项目的注销页面、接口链路、短信验证、会话清理和错误提示。

当前页面已经具备基础交互，但点击“立即注销”后会弹出“检查失败，请求失败，请稍后再试”。本文件记录问题根因和后续实施步骤，后续开发以本文件为准。

## 当前问题

### 用户看到的弹窗

页面调用注销状态检查接口失败后，在 `AccountCancellationScreen.tsx` 中进入 `catch`：

```ts
Alert.alert(
  "检查失败",
  error instanceof Error ? error.message : "注销状态检查失败，请稍后重试",
);
```

### 实际请求

当前实现直接请求：

```text
POST https://djapi.yingbowl.com/h5-client/v2/user/write/off/check
```

实测返回：

```http
HTTP 404
```

```json
{
  "success": false,
  "code": "FAILED",
  "info": "资源不存在"
}
```

因此页面显示错误提示不是用户操作问题，而是注销接口请求链路错误。

### 根因

`/h5-client/v2/user/write/off/*` 属于参考项目使用的 H5 业务接口，不是当前 `djapi.yingbowl.com` 直连 C 端接口。

`pz_steam` 通过 KPI 加密代理访问这些接口：

```text
业务请求 -> 组装 H5 请求和签名 -> AES-256-GCM-HMAC-SHA256 加密
          -> KPI 代理 -> 代理解密并转发 H5 请求
          -> H5 响应加密 -> KPI 代理 -> 客户端解密
```

当前项目只实现了普通 `apiClient` 直连，没有实现这层加密代理传输，所以请求直接落到 `djapi.yingbowl.com` 后返回 404。

另外，当前普通网络层只读取错误响应中的 `message` 字段，没有优先读取 `info` 字段，导致后端已经返回的“资源不存在”被包装成了泛化的“请求失败，请稍后重试”。

### 业务接口

| 阶段 | 方法 | H5 路径 | 请求体 | 结果 |
| --- | --- | --- | --- | --- |
| 检查注销条件 | POST | `/h5-client/v2/user/write/off/check` | `{ "action": {} }` | `data` 为空数组表示可注销；非空数组是阻止原因 |
| 发送注销验证码 | POST | `/h5-client/v2/common/sms` | `{ "action": { "smsTemplate": "WRITE_OFF" } }` | 成功后进入 60 秒倒计时 |
| 提交注销申请 | POST | `/h5-client/v2/user/write/off` | `{ "action": { "smsCode": "123456" } }` | 成功后清理本地会话 |

三个接口都需要当前业务 token，并且 token 放在 H5 请求的 `Token` 头中。不能把业务 token 当作 OAuth Bearer token 使用。

### H5 签名

每次请求都要生成新的时间戳和 6 位随机数：

```text
timestamp = 当前毫秒时间戳
random = 6 位数字字符串
bodyJson = 紧凑 JSON 字符串
signMaterial =
  PZTimestamp={timestamp}&Random={random}&2147483647={encode(bodyJson)}&accessKey=3qXyB7uf
sign = MD5(signMaterial)
```

内部 H5 请求需要至少包含：

```text
Content-Type: application/json
Accept: application/json
PZVersion: 当前 App 版本
PZPlatform: ios 或 android
PZOs: iOS 或 Android
PZTimestamp: timestamp
Random: random
Skey: CLIENT
sign: sign
Token: 业务 token
```

`encode` 使用 `encodeURIComponent`，并额外编码 `*`、`!`、`~`、`(`、`)`，与参考项目 `_encodeForSign` 保持一致。

## 推荐实现架构

### 推荐方案：移动端调用受控业务代理

优先让后端提供一个当前项目自己的注销代理接口，例如：

```text
POST /client/v1/user/account-cancellation/check
POST /client/v1/user/account-cancellation/sms
POST /client/v1/user/account-cancellation/submit
```

后端负责访问 H5 接口、保存签名密钥和 KPI 代理密钥，移动端只携带当前 C 端业务 token。这样可以避免把以下敏感配置打包进移动端：

- KPI 代理 token
- KPI transport secret
- H5 access key

### 兼容方案：在移动端复刻 `pz_steam` 的 KPI 加密传输

如果后端暂时不能增加代理接口，则移动端需要完整实现参考项目的加密 transport，不能只添加 `PZTimestamp`、`sign` 等普通 HTTP 头。

需要实现：

1. AES-256-GCM 加密业务请求。
2. HMAC-SHA256 派生加密密钥和签名密钥。
3. 请求 envelope 的 `alg`、`timestamp`、`nonce`、`iv`、`ciphertext`、`tag`、`sign` 字段。
4. Base64 编码后的 `encryptBody`。
5. 外层请求头 `encrypt: v2` 和 `X-Kpi-Proxy-Token`。
6. 代理响应的完整性校验、时间戳校验、解密和 JSON 解析。
7. 每次重试生成新的 nonce，禁止重复发送相同加密 envelope。

当前项目已经有 `crypto-js`，但它不能单独替代参考项目的 AES-GCM 和 HMAC transport。需要使用 Expo/React Native 兼容的密码库，或者把加密动作放到后端代理完成。

## 页面状态与交互要求

### 页面首屏

- 显示注销不可逆的影响。
- 显示当前登录账号的脱敏手机号。
- 未登录时显示“请先登录”，点击提交后跳转登录页。
- 显示注销影响、提交条件和办理流程。

### 提交按钮

提交按钮只有在用户勾选注销说明后可用。

点击提交后依次执行：

1. 弹出二次确认。
2. 调用注销条件检查接口。
3. 如果返回阻止原因，显示原因列表，不发送验证码。
4. 如果可以注销，打开短信验证底部弹窗。

### 短信验证弹窗

- 显示脱敏手机号。
- 点击“获取验证码”调用 `WRITE_OFF` 模板。
- 发送成功后开始 60 秒倒计时。
- 验证码输入限制为最多 6 位数字。
- 验证码为空时禁用提交。
- 提交时显示 loading，防止重复请求。

### 成功处理

注销申请接口成功后：

1. 关闭短信弹窗。
2. 清除安全存储中的业务会话。
3. 清除 Zustand 内存会话。
4. 断开并清理即时消息状态。
5. 提示注销申请已提交。
6. 返回首页。

### 错误处理

错误提示必须保留后端具体信息，优先级如下：

```ts
info ?? message ?? "请求失败，请稍后重试"
```

至少区分以下情况：

- 网络连接失败。
- 请求超时。
- 401 或业务 token 失效。
- 注销条件不满足。
- 短信发送失败。
- 验证码错误或过期。
- 代理返回 400/404/500。

## 测试计划

### API 契约测试

验证：

- 检查接口路径为 `/h5-client/v2/user/write/off/check`。
- 短信接口携带 `smsTemplate: WRITE_OFF`。
- 提交接口携带 `smsCode`。
- 三个接口都携带业务 token。
- 阻止原因数组可以正确解析为空数组和非空数组。
- `success !== true` 时错误信息使用后端 `info`。

### transport 测试

验证：

- 签名材料中的 body JSON 与实际发送 body 完全一致。
- 特殊字符编码与参考项目一致。
- 外层请求包含 `encrypt: v2`。
- 加密响应可以解密为对象和数组。
- 时间戳过期、签名错误、字段缺失时请求失败。
- 重试时 nonce 不重复。

### 页面测试

验证：

- 未勾选时“立即注销”不可提交。
- 未登录时点击提交显示登录提示。
- 检查返回阻止原因时显示原因弹窗，且不发送验证码。
- 检查通过后显示短信验证弹窗。
- 验证码倒计时期间不能重复发送。
- 注销成功后清理会话并返回首页。
- 接口失败时显示具体错误信息。

## 验收标准

- 点击注销不会再直接请求 `https://djapi.yingbowl.com/h5-client/...` 并返回 404。
- 能看到后端返回的真实错误信息，而不是统一显示“请求失败”。
- 注销检查、短信发送、验证码提交三步请求均能在真实环境完成。
- 注销成功后重新进入 App 不会恢复旧登录态。
- 普通登录、退出登录、个人资料和即时消息功能不受影响。
- 执行以下命令无 TypeScript 错误：

```bash
npx tsc --noEmit
npx expo lint
```

## 实施顺序

1. 先确认后端是否可以提供受控注销代理接口。
2. 如果可以，优先实现后端代理并让移动端调用 `/client/v1` 接口。
3. 如果暂时不能提供，补齐 KPI 加密 transport，再接入三个 H5 注销接口。
4. 先写 API/transport 失败测试，再实现代码。
5. 修正普通网络层的 `info` 错误解析。
6. 完成页面状态测试和真实环境联调。
7. 执行 TypeScript、lint、接口契约测试和页面测试。

## 安全注意事项

- 不要把代理 token、transport secret、access key 写入 Markdown、测试日志或错误弹窗。
- 不要在日志中打印业务 token、短信验证码或完整加密请求体。
- 不要使用用户输入拼接 URL。
- 不要在注销请求失败时清除用户会话，只有服务端确认注销申请成功后才清理会话。
- 重试注销请求前必须确认接口是否幂等；加密 transport 重试必须生成新的 nonce。
