# 盼友圈移动端短视频技术方案

## 1. 目标与项目基础

本方案基于当前 Expo / React Native App，为盼友圈建设移动端短视频 Feed，重点保证上下滑切换、HLS 播放、iOS / Android 兼容，并复用现有登录、接口、Agora 语聊房和后端能力。

当前项目使用 Expo SDK 57、React Native 0.86.3，已有 TanStack Query、NetInfo、Zustand、Reanimated、Gesture Handler 和 `expo-image`。播放器选择 `react-native-video` v7，Feed 列表选择 FlashList v2。

v7 将播放器实例与视频画面分离，提供预加载和手动管理播放器生命周期的能力，适合短视频 Feed。[React Native Video v7 文档](https://docs.thewidlarzgroup.com/react-native-video/docs/v7/fundamentals/intro/) 当前 v7 仍为 Beta，因此必须固定具体版本，并先完成 Expo SDK 57 下的 iOS、Android 原生构建与真机播放验证。[v7 VideoPlayer API](https://docs.thewidlarzgroup.com/react-native-video/docs/v7/player/video-player/)

## 2. 盼友圈功能范围

移动端 Feed 支持 `hot`、`latest`、`follow` 三种内容流，以及上下滑切换、自动播放、暂停 / 恢复、静音切换、循环播放、点赞、评论、举报、关注、分享、作者主页、关键词搜索、话题搜索和播放上报。

发布侧支持 VOD 视频上传、正文、话题、@ 用户、自主声明、我的作品和审核状态。客户端通过 `/client/v1/media/video/uploadSign` 获取火山 VOD STS，再由上传组件完成直传；发布接口提交 `vid`。封面由后端转码工作流生成。前端发布资格校验只负责体验，后端发布接口负责最终授权。

## 4. Feed 与分页接口

```text
POST /client/v1/moments/video/feedList
{ tab: "hot" | "latest" | "follow", cursor: "", size: 10 }
```

后端返回 `list`、`nextCursor` 和 `hasMore`。使用现有 TanStack Query `useInfiniteQuery` 管理分页。游标是服务端 ES `search_after` 的不透明值，客户端只保存并原样传回，不解析、不拼接、不本地排序。

- 首屏使用空游标，接近列表尾部时加载下一页。
- 依据 `videoId` 去重，按 Feed tab 隔离缓存。
- 切换 tab 时重置对应的游标和播放位置；离开页面再返回时恢复位置。
- 进入 `follow` tab 前检查登录状态。该接口虽标注免 token，但后端业务仍要求登录，错误表现为业务失败，不一定是 HTTP 401。
- 使用请求取消或请求序号处理竞态，防止旧 tab 的迟到响应覆盖当前 Feed。
- 刷新失败时保留已有视频；加载、空内容、错误和加载更多分别展示状态。

Feed 只返回审核通过的视频。刚发布或刚通过审核的内容可能因 ES 异步同步暂时不在 Feed；“我的作品”可展示审核中内容。

## 5. 播放器池与切换

初期播放器池最多保留两个活动播放器：当前视频播放器负责展示和播放，下一条播放器静音预加载。上一条视频暂停后释放；若真机测试证明返回体验需要，再考虑增加第三个播放器槽位。预加载数量需要受限，避免内存、网络和原生解码器资源随 Feed 长度增长。

播放器由 `VideoPlayer` 实例集中管理。播放引擎负责调用 `preload()`、`pause()`、`play()`、`replaceSourceAsync()` 和 `release()`。复用实例切换 source 时先清理旧 source；同一实例同一时间只绑定一个 `VideoView`。[播放器生命周期和预加载 API](https://docs.thewidlarzgroup.com/react-native-video/docs/v7/player/video-player/)

页面吸附到新视频后，播放引擎暂停旧播放器、激活新播放器、确保 App 在前台后播放，并为下一条开始预加载。不要在每帧滚动事件中更新 React 或 Zustand 状态，只在吸附完成、当前视频 ID 确认变化时更新播放状态。

```text
idle → loading → 首帧就绪 → playing
                  playing → buffering → playing
                  loading / playing → error
```

收到 `onReadyToDisplay` 后隐藏封面。播放失败时保留封面，执行一次地址刷新或重试；失败后停止自动重试，避免请求风暴。[播放器事件](https://docs.thewidlarzgroup.com/react-native-video/docs/v7/player/events/)

## 6. 视频展示与后端播放源

PC 端盼友圈的视频尺寸规则为宽度 100%、高度自适应，视频采用 `contain`；留白区域以封面模糊填充。移动端延续该行为：满屏竖视频占满可用 Feed 区域，非满屏比例的视频使用 `contain`，背景由封面模糊填充。使用 `expo-image` 预热封面；播放器首帧渲染前显示封面，首帧到达后再隐藏。

Feed 当前返回实时签名的 `url`。数据库内转码相对路径不是客户端播放地址；签名 URL 是短期凭证，不写入长期本地缓存。

后端新增字段用于控制 MP4 / HLS 时，建议客户端契约如下：

```ts
type CommunityVideo = {
  videoId: string;
  coverUrl: string;
  streamType?: "mp4" | "hls";
  url: string;
  duration: number;
};
```

客户端按 `streamType` 构造播放器 source；字段缺失时按双方约定的兼容策略处理。若后端同时提供 HLS 和 MP4 地址，可在 HLS 失败后刷新签名 URL 并尝试 MP4。HLS 多码率切换依赖后端 master playlist、CDN 分片和原生播放器协作。PC 端通过 HLS.js 执行的 `recoverMediaError()` 不适用于 React Native；移动端使用播放器自身的错误事件和恢复流程。

## 7. 播放上报

播放上报依照播放器真实状态累计时长。暂停、缓冲、seek、后台状态和视频离开有效播放窗口时暂停计时。翻页切走、退出页面、视频结束或播放器销毁时结算：

```text
POST /client/v1/moments/video/playReport
{ videoId, durationMs }
```

游客不调用播放上报；`durationMs <= 0` 时跳过。后端按同一用户和视频 300 秒去重，有效播放阈值为 3000 毫秒。上报失败静默处理，不阻断播放，也不触发全局登录或实名弹窗。

## 8. 互动、话题与鉴权

视频点赞接口接收显式方向 `{ videoId, liked }`，服务端不自动翻转状态。客户端请求成功后更新 `liked` 和本地计数，并使用 loading 锁防止重复提交；若使用乐观更新，失败时必须回滚。评论点赞使用相同模式。

评论列表使用游标分页，一级评论包含二级回复。关闭评论面板或切换视频时取消旧请求，或以 `videoId` / revision 防止迟到响应写入新视频。评论发布经过同步 AI 文审；业务失败时保留输入并展示错误。评论作者和视频作者都可能拥有删除权限。

话题候选由运营维护，客户端不能创建话题。正文 `topics`、`mentionUsers` 可能以 ID 到名称字典返回，也可能带 `offset` / `length` 实体。优先使用实体位置渲染跳转；只有字典时再做校验后的兼容解析。用户手打的 `@`、`#` 不自动转成实体链接。

发布内容的 `mentions` 和 `topics` 是结构化数组，正文 offset / length 按 Unicode 码点计数。正文不能 trim，否则实体位置失效。提交前校验 ID 和实体片段；话题候选 ID 必须来自后端接口，因为非法 ID 可能被后端静默丢弃。

所有请求复用项目的 `apiClient`，包括业务 token、响应解包、401、实名拦截和 token 刷新逻辑。业务 token 放在 `token` 请求头。`playInfo`、`declaration/list`、`topic/list`、`mention/list` 实际需要登录；`topic/hotRank/list` 可免登录。举报类型和自主声明由后端动态下发，不能写死在客户端。

## 9. 音频、前后台和交互

项目已有 Agora 语聊房和后台音频配置，使用 `MediaSessionCoordinator` 统一仲裁：

```text
Agora 语聊房 / 通话 > 用户主动播放的短视频 > 静音预加载
```

- 进入语聊房时暂停短视频；短视频预加载播放器保持静音。
- Feed 离开、Tab 切换或 App 进入后台时暂停视频。
- App 回到前台时，仅当 Feed 仍可见且没有更高优先级音频会话时恢复。
- 默认关闭短视频后台播放和画中画。
- 默认静音自动播放；用户主动开声后记住当前 Feed 会话的静音状态。
- 单击播放 / 暂停，双击点赞；竖向手势交给分页列表，按钮保持独立点击区域。
- 控制层可在用户操作后约 3 秒隐藏；评论或分享面板打开时维持对应交互状态。

## 10. 发布、我的作品与审核状态

发布页流程为：校验登录和发布资格、选择视频并检查格式/大小/时长、调用 uploadSign 获取 STS、映射上传 SDK 字段并上传 VOD、取得 `vid`、编辑标题正文和实体、提交发布接口、展示审核状态。

作品状态至少区分 `REVIEWING`、`APPROVED` 和 `REJECTED`。驳回原因只对作者本人展示 `violationTypes` 与 `extraDesc`，不显示内部机审原因或内部备注。上传完成不代表视频已审核通过，也不代表它会立即出现在 Feed。

## 11. Expo 与原生接入

项目已经有 `ios/`、`android/` 目录和多个自定义原生插件。接入 v7 时，按官方说明添加 Nitro Modules 和 Expo config plugin，检查插件组合、自动链接、Reanimated 补丁脚本及后台音频配置。原生依赖变化后重建 iOS / Android 开发包；只启动 Metro 不算集成完成。不得覆盖项目已有原生修改。

TheWidlarzGroup 提供竖屏 Feed 示例，可参考吸附、可见度触发、预加载窗口和指标设计；示例依赖旧 Expo SDK 和早期 v7 Beta，不能作为本项目兼容性依据。[React Native Video Feed 示例](https://github.com/TheWidlarzGroup/react-native-video-feed)

## 12. 监控、验收与实施顺序

播放指标记录 Feed 请求耗时、流类型、播放器创建 / 释放数量、首帧时间、缓冲时长、失败原因、网络类型、设备型号和播放上报结果。

| 指标 | 首版目标 |
|---|---:|
| 已预加载视频滑入后的首帧 P95 | ≤ 300ms |
| 普通网络冷启动首条视频首帧 P95 | ≤ 2.5s |
| 播放成功率 | ≥ 99.5% |
| 同时播放 / 发声视频数量 | 1 |
| 同时活动播放器数量 | ≤ 2 |
| 连续快滑 200 条后的内存 | 无持续增长趋势 |

建议按以下顺序实施：

1. **播放器 POC**：固定 v7 Beta 版本，完成两端原生构建；验证 MP4、HLS、首帧、预加载、换源、释放和错误处理。
2. **Feed 核心**：接入 FlashList、cursor 分页、双播放器池、封面切换和位置恢复。
3. **互动功能**：接入点赞、评论、话题、搜索、关注和播放上报。
4. **发布功能**：接入 VOD 上传、实体编码、我的作品和审核状态。
5. **音频与设备验证**：覆盖 Agora、前后台、来电、耳机、弱网、旧款 iPhone 和中低端 Android。

进入 Feed 全量开发前的门槛是：iOS 和 Android 原生构建均通过；预加载视频首帧与切换稳定；快滑后播放器数量回落；短视频与 Agora 不同时发声。若 v7 Beta 阻塞这些检查，先锁定可用版本或收敛接入范围，再推进业务功能。
